## Implementation and boundaries

The current work implements the [authoritative incoming configuration contract](evidence/implementation-2026-09-11-round7/x13-next-configuration-contract.md). The authenticated Sales Return configuration reader requires explicit selected company, branch, year and configured Return book. It reads settings, columns, book and year in one RepeatableRead snapshot, resolves source defaults and the labour precision clamp before the final override, and returns stable source field IDs with effective zero/nonzero width predicates. It preserves raw whitelisted settings, diagnoses unsupported or ambiguous imports, and never accepts policy, widths or comparison caches from the request.

This is a calculation prerequisite. It does not enable a numeric writer. Unresolved Style edition remains a diagnostic for that field, independent of resolved ordinary calculation fields. Source nominal widths encode the zero predicate; they are not measured desktop pixels or browser CSS widths. Hidden cache/identity fields remain distinct and unavailable as ordinary commit targets. New-row labour defaults do not overwrite saved/source values.

Column settings now use the original desktop company + form family + original column identity. The dedicated Styles/Columns editor and versioned mutations preserve that identity, contain duplicate rows and reject stale observations. Changes patch only explicitly touched values, keeping untouched NULLs and imported values intact. The page reads fresh per-form capabilities, filters and pages through the selected company, and refuses to merge pages when their collection observations differ. Scope/filter epochs prevent old responses from replacing a new editor. Conflict, deleted-row, revoked-rights and uncertain outcomes retain the draft and require explicit reload. Its CSV export is explicitly limited to loaded rows and uses the inherited NULL-to-blank CSV encoding; it is not a lossless migration/export format. The existing URLs and flat create/import/list envelopes remain; old PUT/DELETE callers must supply the complete family identity and observed version. Unversioned mutations are deliberately rejected with reload guidance. The verification below records this bounded implementation and its retained limitations.
