Hidden c42 is accumulated only from supplied source state; it is not a new editable control. Columns 26/37 and other unlisted values do not become invented totals.

An empty supplied row set leaves numeric totals blank. `UpDown=true` preserves the exact prior total object/counters without numeric reads; the caller's bill callback still runs after a calculated row event.
- The bill callback independently rounds full outgoing and incoming legs to whole units, then assigns the payment/received difference. Manual tax survives when both numeric tax caches match. Otherwise tax uses the current percentage and resolved tax precision, while replacement caches follow their own two-place source formatting. The total is rounded separately to whole units.
- Both outstanding amounts are computed before inactive-side clearing. Closing uses the post-clearing values and the original three opening-sign branches. The exact mathematical closing value remains separate from its two-place label; zero closing retains the previous label color. Unknown opening produces an explicitly unavailable closing, with no fabricated zero or stale numeric label.
- The composed reducer retains every accepted original event, including repeated same-value events. Text-only events update their row/journal without aggregate or bill callbacks. Source guard skips retain the whole previous state. Any row, aggregate or bill failure rolls back the entire attempted transient event, including every row/cache, totals, tenders and both journals; the attempted text remains available.
- A complete source-ordered grid requires explicit contiguous ordinals and unique opaque identities. Ordinals are distinct from saved serial keys. An active event must target the matching identity and ordinal. Even text-only changes must preserve this invariant.

The numerical contract is a declared exact-decimal mathematical profile, not measured Windows `Double`, `Conversion.Val`, `Strings.Format`, locale, signed-zero or ActiveX acceptance. Inputs and reusable results are bounded to 36 significant digits, 18 decimal places and magnitude below 10^36; finite plain strings and ordinary blanks/spaces are supported. Invalid prefixes, exponent/control-character forms, nonfinite values and unsupported precision produce diagnostics. The grid bound of 10,000 rows is an explicit resource profile, not a recovered desktop limit. Source `Math.Round` uses the separate half-even primitive; subsequent arithmetic returns to a local precision-100 Decimal clone. No global precision setting is changed.
