## X14/X25 — concurrent saved-order image changes

The saved-order image token now includes the image's persistent revision as well as its saved parent identity. Revision metadata survives deletion, so replacing, deleting and recreating a photo invalidates earlier clients even when identical bytes return. All current application image writers lock the actual shared image identity and advance its revision in the same transaction as the bytes and tag index. Two different orders sharing a tag image therefore cannot both commit with stale observations.

Migration `20260911060000_image_revision` adds the web-only revision table with forced tenant RLS. Existing bytes and desktop image identities are unchanged. The token also fingerprints raw stored bytes/metadata and tag-index state, including unavailable or malformed historical images. A conflict uses the existing route diagnostic, preserves the newer photo, and requires Reload image before an intentional retry. Generic image editors advance revisions and invalidate order clients, but their own older mutation request contract still lacks an optimistic client token. Out-of-band import/restore still requires its operational maintenance barrier.
