Disposition: no confirmed implementation defect within the frozen `canonical-postgresql-fixed-decimal-v1` contract. This review inspected source only. It did not run the reader, database tests, build, browser, SQL Server or desktop executable, and does not independently claim those execution results. No product or test files were modified.

The review compared `web/apps/api/src/modules/shared/desktopAccountBalance.ts` with the frozen Round12 observation contract, primary `DC_Main.cs:1463–1487`, the current `AC_DATA` schema and the independent test source. Exact revisions are pinned in the adjacent `.refs.json`.

- **Arithmetic and NULLs:** the SQL at reader169–176 preserves `SUM(CR_AMT-DR_AMT)`, so subtraction precedes aggregation and a NULL operand does not become a zero leg. The two metal CASE expressions preserve the source G/S filter, plus versus every-other-sign negation, nullable fine contribution and opposite/other-type literal zero. This matches primary1471/1479. No grouped row returns the initialized zeros; a present NULL group remains NULL and makes complete-helper status unsupported. Partial known amounts are not mislabeled as complete helper execution.
- **Numeric presentation:** `fixed` at187–196 operates on SQL text, preserves exact fixed-scale decimal values, pads F2/F3, normalizes mathematical zero and refuses unsupported sums. It performs no money/weight Number conversion and invents no rounding beyond the current storage-scale profile. `CR_AMT`/`DR_AMT` are Decimal(18,2), `FINE_WT` Decimal(14,3), and SUM can widen precision. The36-digit bound is explicit containment. Source1475–1477/1483–1485 Format→Double/DBNull/locale/binary behavior remains outside this exact-decimal claim.
- **Scope and clocks:** the single materialized candidate observation uses tenant/company/location/year/account and inclusive `ENTRY_TIME`, with no book, voucher or VCH_DATE filter. A/B apply mode comparison; C omits it, retaining NULL/other data types. The opening group changes only the cutoff to strict-before. The qualified cutoff uses a local whole second; calendar checks do not use JavaScript Date/timezone rollover. Stored microseconds are preserved in raw/physical observations. NULL-time and later rows are outside this narrow source predicate. Recovering lost import clocks or constructing the source voucher date-plus-clock remains the caller's unresolved task.
- **Ambiguity and snapshot:** normalized discovery exposes the declared case/padding aliases; exact rows alone supply supported groups. Relevant noncanonical keys/comparison text invalidate displayed phases while preserving raw groups and diagnostics. This is not universal SQL Server collation emulation. The same SQL statement supplies candidate rows, physical row_id/xmin/ctid, exact raw business scalars and both groups. A matching tenant context and RepeatableRead/Serializable transaction are checked before returning an observation.
- **Version boundary:** the hash binds profile, exact scope/account/mode/cutoff, all observed raw/physical rows and both raw groups. Diagnostics and formatted results are deterministic consequences of those versioned inputs and implementation profile. Eligible other-book insertions and present-row replacement are dependencies. An empty→insert→delete cycle can restore an empty observation hash; later-than-cutoff and NULL-time changes can also remain outside this token. This is an observation token, not a reservation, authenticated mode history or universal ABA guard.

The reader deliberately does not authenticate mode or complete a session bootstrap. A future caller must observe authoritative mode/context generation and ledger rows coherently in the same transaction, then bind those dependencies into any downstream replay version. Its `helperClosing` is the inclusive result of `MsAcBal`, not the later `BILL_TOTAL` closing calculation. Existing v1/v2 Return closing capability must remain unavailable until those separate authorities and conversion/runtime prerequisites are established.
