## Implemented read profiles

The new `mfgLot.ts` API is bounded to configured `BOOK_DATA.MAIN_BOOK` families `MFG STNG ISU` and `MFG STNG REC`; display names and fixed book numbers do not determine family. Every saved read uses tenant/company/branch/year/book/voucher. The browser has separate issue and receipt routes with the corresponding action's view rights, integrated by root. No create/edit/delete function is exported or advertised.

Saved browse can operate even when manufacturing stage configuration is ambiguous. Source selection requires one active MFG_MAST record, the actual selected book direction I/O consistent with any supplied MFG_MAST.IN_OUT, and Setting ENTRY_TYPE S. Receipt's bounded material selector additionally requires LAST_TRAN S. Effective desktop lot/order/one-form/ledger mode remains unverified and is not invented from CO_SET. All writes remain unavailable.

The desktop parent/component contract uses saved parent SR_NO and component SR_NO/ISR_NO directly. OLD_SRNO and REP_* are separate source references. No array index or OLD_SRNO fallback attaches a child; an orphan or duplicate identity produces a clear validation failure. Header, parents, components, manufacturing projections and stock movements preserve all database business fields. PostgreSQL converts numeric cells to exact strings before JSON parsing, preserving large decimals and decimal scale; DB-rendered dates and timestamps preserve the business clock. Blank/null remain distinct. Physical stock contributor row IDs are exposed as `stockRowId` in addition to voucher/parent/child keys, so repeated physical movements retain their identities. A SHA-256 snapshot version is returned for comparison; there is no mutation concurrency guarantee in this read-only stage. Saved voucher lookup resolves an exact persisted key first (up to the table’s eight-character width). Only when no exact key exists does a short numeric reference receive the five-character display padding. This keeps distinct imported `1` and `00001` entries reachable and supports six/eight-character saved references without changing writer numbering. Blank, oversized or control-containing input produces400 rather than a numbering exception.

Current account and item names are supplied separately as `displayLabels` for saved browse, saved documents and source inspection. Account names are restricted to the selected tenant/company/branch, with an unambiguous company-global blank/null branch fallback only when no exact branch row exists; a conflicting name remains unnamed. Item names use the selected tenant/company. Saved codes and any imported fields remain unchanged. The saved snapshot version excludes these current master labels, so a master rename does not masquerade as a saved voucher change. The browser marks these additions as “Current name” alongside the raw saved code, including each component and source contributor.
