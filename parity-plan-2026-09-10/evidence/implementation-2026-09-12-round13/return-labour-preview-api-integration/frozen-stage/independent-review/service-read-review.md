# Saved Return labour preview API — independent source review

No confirmed implementation blocker found in the complete observed new service, internal bill observer hook and three route/policy additions. This is a bounded source review of the staged revision. Tests, mounted API, database, compiler and browser were not executed by this reviewer. The owner is still finalizing tests; these hashes pin this observation rather than claiming a future revision is unchanged.

The new service detaches exact scope/event/prefix own-data inputs before asynchronous work. Fixed positive five-digit vouchers, complete unpadded ASCII scope,64-character lowercase hashes, bounded dense journals, known event shapes and editor bounds are checked without client raw masters/policy/contexts. Repeated money and labour intent is retained. Money field IDs are runtime-allowlisted even though the exported event type uses string. Transport caps are new profile constraints, not historical Windows limits.

The new route handlers preserve the existing requireAuth preHandler and add early no-store, exact retained context header pair matching, existing strict incoming query selection and the separate RR helper. GET and both POSTs are assigned Sales Return/read policy; no Update right or numeric save is granted. The new helper revalidates subject/scope/epoch/unknown-ledger, selected principal, stored scope and View authority inside one RepeatableRead transaction. Route authority and business/master observation therefore remain separate checks within the documented snapshot limits. The service always supplies the fixed Sales Return form and never trusts an action or role in the body.

The bill observer export and optional beforeProjection hook preserve old versions/DTO construction and old callers' default behavior. The hook runs after the old row/document/configuration/master hash and additional bill settings/tax/account observations are assembled, but before row/header projection. The new base binds the complete admitted context, semantic versions, scope/voucher and old bill replay version. Historical labour codes are re-observed completely in the same Tx, including aliases/raw fields/xmin/ctid, and each supplied historical observationVersion must match before projection or replay. Repeated instances of a code cannot supply inconsistent versions. The prefix digest includes exact ordered events plus sorted distinct dependencies; it is a correspondence token, not a write receipt or bearer authority.

Opaque row identity is resolved against the whole saved grid and trusted SQL-order state; no client index, source row, formatted OLD_SRNO or Number-converted serial chooses a parent. Whole-grid eligibility remains the old bill profile. Labour width/capability comes from server configuration. Lookup reconstructs the old prefix and qualifies a private copy without applying the candidate or invoking its calculator; only the exact four qualified raw master cells are returned. Append reconstructs every old event and applies exactly one new money or composed labour event. Same-code Enter and tag04/05 still use the composition callback path. The new service neither reseeds caches nor coalesces events nor computes bill only once at the end.

A historical replay failure stops with a prefix conflict; it does not shorten or silently rebase history. Candidate calculation/editor/output refusals retain the complete prior reconstructed row/bill prefix, with no candidate in recovery.events. That candidate422 rejection travels through the RR coordinator as an outcome and is thrown only after final session/live validation and transaction completion. The observed owner correction bounds the whole error envelope including recovery; oversized envelopes become a small unsupported-output refusal without truncating the prefix into a different accepted value. Other infrastructure errors propagate, and stale base/master/identity errors do not supply replacement authority.

No DML, numeric writer, account posting, session mutation, nested withTenant or nested transaction appears in the new service. The internal bill/row/labour observation chain shares the admitted Tx; pure copy/reducers cannot persist changes. Intentional route onResponse POST audit is separate from business/session/config read preservation and must be measured separately in actual API tests. This review does not certify audit atomicity.

Remaining qualifications are unchanged: permissions and masters are as of the RR snapshot; known serialization/deadlock conflicts require explicit retry. Existing book configuration and metadata/version readers own their established eligibility rules. Physical hashes cover extant-row changes and observed membership, not every absent→insert→delete cycle or restore. Ledger mode and closing remain unavailable. A callback contract does not mechanically forbid arbitrary DML by future callers; the current reviewed callback chain is read-only. Old-profile runtime regression, full output/identity client validation, browser lifecycle/ABA/fault tests and actual unchanged-data snapshots are still independent acceptance work.
