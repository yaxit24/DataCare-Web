# Separate RepeatableRead session read snapshot — staged contract

Preparation and implementation profile only. No endpoint, route, JWT, preview writer, existing command coordinator, or active tree changes are authorized by this file. The fixture is authored before the new module and names literal outcomes; the future scripted SQL tests do not emulate real PostgreSQL isolation.

Exports: `SESSION_CONTEXT_READ_SNAPSHOT_VERSION = 'session-read-repeatable-snapshot-v1'`; `SessionReadSnapshotIdentity` (the eight retained identity keys including own coYear:string|undefined); `SessionReadSnapshotPolicy` exactly `{form,scope:{tenantId,coCode,lcCode,coYear,coBook}}`; `SessionReadSnapshotAdmission` exactly `{context:AuthenticatedSessionContext,principal:Principal,authorization:FormAuthorization}`; `SessionReadSnapshotError(code,statusCode,message?,form?,action?:'read')`; `withSessionContextReadSnapshot(prisma, suppliedIdentity:unknown, suppliedPolicy:SessionReadSnapshotPolicy, work(tx,admitted):Promise<T>):Promise<T>`.

Before any await, detach descriptor-validated plain own-data identity and policy, reject unknown/symbol/accessor/non-enumerable keys and malformed canonical epoch; no caller role, action or adminOnly property. Complete year and book are required. Fixed policy tenant/company/location/year must equal the retained identity. Policy is trusted server-owned input, not request authority. Public mandatory header-pair and exact unpadded query parsing remain the future route's separate responsibility.

Use one `withTenant` RepeatableRead transaction. Tenant setup may establish the MVCC snapshot. Check actual tenant and isolation, then make the first application row lock the exact tenant/session `FOR SHARE`. Verify immutable subject, separately query `clock_timestamp()` after any wait, then compare current scope/epoch and parse the exact unknown ledger context. Do not lock LOGIN or upgrade the session lock. Resolve the selected principal, immutable login company fallback, current stored configuration and fixed read/View permission in this same snapshot. Refuse forced reset. Admitted identity and authority containers are detached and frozen. The principal's credential company remains distinct from context.loginCoCode.

Callback uses this Tx for every business/configuration/master read. No nested transaction, normal wrapper, external side effect, audit, ledger/session mutation or application DML is allowed by the caller contract. The helper cannot mechanically prevent arbitrary callback DML and does not set PostgreSQL transaction READ ONLY (row locks are required). Tests measure raw values plus xmin/ctid, allowing row-lock xmax changes. Intentional HTTP onResponse audit is outside this helper and needs separate API attribution.

Before publishing, re-read the complete session subject/scope/epoch/ledger and revoked/expiry with SQL clock_timestamp; require exact admitted identity/ledger. Return only after transaction commit. The final clock is a statement boundary, not a proof about the exact later commit instant. P2034, 40001, 40P01, and P2010 wrapping either SQLSTATE map to409 preview-snapshot-conflict, never automatic retry. Other failures, including unknown connection/commit exceptions, preserve the original error. Scope errors preserve code/status; principal missing becomes401 session-invalid; View denial403 forbidden retains form/action read. No tokens, receipts, JTI, context epochs, mode or expiry are written.

A selection/refresh/revoke winner may produce a snapshot serialization conflict after waiting. A SHARE winner delays those UPDATE actors until commit. Configuration and rights are as of the RR snapshot, not latest-at-response or universally locked. This does not cancel already admitted business writers or establish any new runtime desktop authority. All14 DB schedules are prospective, and their explicit actor-owned changes are separate from the read helper's unchanged-state claims.
