## Preserved write behavior and changed admission

All six original authorization template literals and all48 original Sales Order template literals remain byte-identical and in the same order. The extracted order callback statements match after indentation normalization, except the former PrismaClient argument passed to `createSalesOrder` becomes `undefined`: the explicit `lifecycle.tx` branch uses the caller transaction, so the extracted callback has no independent client to use. `extraction-comparison.json` records the exact comparison/hashes. This is a text/source equivalence check, not a compiled or runtime proof.

The guarded entry deep-clones the full Sales Order input (retaining Date objects), freezes its copied scope, and uses that exact scope for both admission and the work callback. Caller mutation after a lock wait cannot replace the command company, amounts or children. Tour mode is rejected by this new Sales-only entry. Ordinary/Tour/internal legacy wrappers remain separate; all other financial routes still require later adoption.

The wrapper owns one tenant-bound ReadCommitted transaction. Its first application row lock is one exact auth_session FOR SHARE, before business/advisory/document/configuration locks. It separately samples database expiry after the row-lock wait; resolves fresh plain principal, exact stored scope and form authorization within the transaction; retains the SHARE lock while the financial callback runs; and performs a final full subject/scope/epoch/unknown-ledger/live check before returning. No session refresh hash, epoch, receipt, last-used or revocation UPDATE is issued by the helper. The final check detects callback-local context or ledger changes as well as expiry and causes the callback's business writes to roll back.

The trusted policy/scope envelope is validated as own data properties with exact keys, string scope, a known action and boolean adminOnly if present. Identity is separately copied without invoking accessors, validates exact epoch via the existing parser, and is compared to the locked row. ScopeError status is preserved; known SQL conflict metadata maps to409 with no retry; unrelated domain/timeout/connection/COMMIT-transport errors propagate unchanged. An ambiguous COMMIT failure is never labeled confirmed rollback.

This establishes ordering only against conflicting mutations/revocations of the same session. A command winning SHARE can finish before queued selection/refresh/revocation; those actors do not retroactively cancel it. The final SQL live check is a final-statement boundary, not a claim about the later exact COMMIT timestamp. ReadCommitted does not provide an immutable configuration/rights snapshot. Other-session CO_SET/USER_SET writers and reset predicates that do not match this immutable credential company remain the documented limits in the frozen contract.

Do not add LOGIN_MAST row locks after session SHARE: password reset already locks credentials before sessions. No callback may select/refresh/revoke/touch a session or perform external side effects. The fault-injection DB tests intentionally violate that callback contract to prove rollback, without installing such mutations in any production financial path.
