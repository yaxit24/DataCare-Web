# Five additional order commands — independent source review

Disposition: no confirmed blocker in the inspected staged revision. This is source and extraction comparison only. No compiler, unit/DB test, browser, transaction or business callback was executed by the reviewer. The owner was still preparing tests; their eventual results and root integration are separate evidence.

The five fixed entries are Sales create/cancel and Tour create/edit/cancel. Each obtains its form/action from its exported entry, rejects a conflicting supplied family, detaches the complete input with structuredClone before any admission wait, freezes the scope, and uses that scope for both admission and the private transaction callback. Three saved-mutation entries require an exact lowercase64-hex version with a separate length check, so missing/uppercase/terminal-newline values cannot pass even though the pre-existing route regex alone accepts a terminal newline. The request adapter supplies retained req.session authority and original creator/deleter, not body identity; missing sid/epoch has no wrapper fallback. The existing Sales edit entry remains separate and unchanged in behavior.

A literal text comparison confirms that create's entire synchronous preparation and run callback is byte-identical to the pinned baseline (24,971 characters). Cancel's original callback matches the extracted callback after removing leading indentation only (2,329 normalized characters). The surrounding full diff contains formatting changes plus the declared extraction/entries. Thus the extraction retains the same number-allocation locks, exact voucher/hidden identities, source/calculation handling, period checks, row/child writes, ledger/Rojmel, imported-NULL and six-digit clock restoration. Cancel retains persisted-version/issued checks, reversal of all nine order tables, exact hidden TEMP removal and DELETE_DATA insertion in the same supplied Tx. A later throw propagates through the one command transaction. This comparison verifies code placement/order, not actual rollback or numerical desktop equivalence.

The callback receives the command helper's existing ReadCommitted Tx. No new nested withTenant is introduced: create uses prepared.run directly, cancel uses runSalesOrderCancelTx, and Tour edit uses the prior replacement callback; replacement's lifecycle branch continues with the same Tx. Internal create/cancel wrappers still establish one tenant transaction, and internal Sales/Tour callers still allow their prior optional versions. New HTTP Tour PUT/DELETE version requirements are the deliberate agreed web improvement; current Tour page already supplies selected.version for both. Sales retains required date/full component-array adapter, while Tour retains date default and its old flattened-component input adapter plus existing multi-child replacement refusal.

Existing command admission takes session SHARE before order locks, validates live authority and complete scope, then checks full session context/live state again after the callback. No new callback takes LOGIN_MAST or auth_session locks after financial locks. Create still takes voucher allocation then hidden-number locks; edit/cancel retain the per-voucher lock before saved-header/version reads. This does not prove global deadlock freedom, freeze rights/configuration changes from other sessions, make unconverted writers safe, supply create idempotency, or guarantee exact COMMIT-time expiry. A lost successful create must not be automatically replayed. Cancellation/refund, order adjustment, consumption, images and unrelated writers remain outside these five entries.

The staged unit file intentionally mocks command admission. Its fixed-authority and first-real-business-query checks support entry wiring and detached scope, but do not by themselves execute all26 independent schedules, nested amount/Date/child detachment, complete write sets or concurrent transactions. Its handler check reads route source text; it is a static wiring assertion rather than a mounted HTTP request. These are coverage qualifications, not discovered runtime defects. Root/owner's separate real PostgreSQL and HTTP checks must be attributed independently.
