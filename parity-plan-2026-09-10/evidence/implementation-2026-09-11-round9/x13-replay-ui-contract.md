# X13 saved Incoming Return calculation preview: UI contract

This Round9 contract describes a **nonpersisting row calculation preview**. It complements `x13-next-server-replay-contract.md` and `x13-replay-validation-matrix.md`; it does not extend the numeric writer, original-sale admission, stock movement, refund or accounting contracts. Checkpoint29 was frozen before implementation authorization. No earlier evidence is changed by this note.

## 1. Existing boundary and owned integration

The existing `apps/web/components/SaleReturnSavedPanel.tsx` loads the full company/location/year/configured return-book/voucher identity, reads exact raw strings and NULLs, and edits only permitted HUID, Receive Item description and employee metadata. `apps/web/lib/salesReturnForm.ts` validates raw header and line identities, retains original SR/OLD/instance/tag identities, and protects asynchronous observations with scope generations. The separate legacy form in `apps/web/app/(app)/txn/sale-return/page.tsx` remains mounted under a hidden container and uses Number-based legacy inputs. **No preview value, cache or event may enter that form, its calculation adapter, its Save handler or the metadata PUT.**

The bounded implementation owns a new `SaleReturnReplayPanel.tsx`, new `salesReturnReplay.ts` helper and focused web tests, with minimal integration in the saved panel. A new separate real-stack journey is integrated by root. Avoid shared VoucherList, shared API-client behavior, generic keyboard navigation, schema and financial routes.

Opening preview requires a clean, fully loaded saved metadata observation. While preview is open, including a pending bootstrap request, freeze metadata inputs/save and local saved book/voucher/load actions. Closing preview is an explicit discard action. Closing the saved card discards both modes; changing global business scope immediately removes the old context and invalidates all old completions. An unchanged metadata reload/save replaces the saved observation and must remount the preview even if its business hash is unchanged. This is an observation generation, not a React key based solely on a version string.

## 2. Agreed wire contract

Root owns routes and owning Sales Return View authorization; service ownership is `tour_order_ui`, trusted projection/core ownership `report_children`. Both routes require explicit `coCode`, `lcCode`, `coYear`, `coBook` query parameters from the loaded saved document.

- `GET /sales-returns/:vchNo/incoming-replay-state` returns `contractVersion`, `profile`, exact `scope`/`voucherNo`, `replayVersion`, `documentVersion`, `configurationVersion`, embedded authoritative `configuration`, `rows`, and `{canPreview,canSaveNumeric:false}` capabilities.
- Each row contains the existing six-field saved `identity`, opaque 64-hex `rowIdentity`, storage-keyed `raw`, numeric source-column-string-keyed `visible` and eight `caches`, `editorTextByField`, twelve `fieldCapabilities`, and diagnostics. Unsupported rows remain inspectable with false capabilities.
- Each field capability is `{fieldId,allowed,reason,maxLength:10,editorDecimals:2}`. Stable IDs are `x13.primary-incoming.c19`, c20, c21, c23, c24, c25, c26, c27, c28, c36, c37 and c38. Captions come from the embedded configuration column catalog; renamed captions never identify events. `configurationVersion` must equal `configuration.version`.
- `POST /sales-returns/:vchNo/incoming-replay` body is strictly `{replayVersion,rowIdentity,events:[{fieldId,editorText}]}`. The complete ordered journal has 0–100 entries. Never send scope in this strict body or echo raw, visible, caches, policy, width, source reference, context, header or calculated totals.
- Success binds the same scope/voucher/versions/row and returns `baseline:{visible,caches,editorTextByField}`, `preview` of the same shape, original events, `aggregateRequired`, and `canSaveNumeric:false`. The response must match the exact requested event sequence before publication. A successful preview does not change its saved-document token.
- The saved-card launch requires `documentVersion === selected.document.version`. A mismatch requires explicit saved-document reload; do not attach a fresh preview baseline to a stale visible saved card.
- 400 rejects malformed input; 403 removes access; 404 removes the observation; 409 rejects stale composite observation or identity; 422 contains unsupported projection/field/calculation with event index, attempted event and diagnostic where relevant. A failed response cannot become an applied preview.

Final DTO names are now published in `apps/api/src/modules/sales/saleReturnIncomingReplay.ts`: `SaleReturnIncomingReplayState`, `SaleReturnIncomingReplayRow`, `SaleReturnIncomingReplayResult`, `SaleReturnIncomingReplayCellSnapshot`, `SaleReturnIncomingReplayFieldCapability` and `SaleReturnIncomingReplayRecovery`. Ready snapshots have 63 visible source cells and exactly eight separate comparison caches. Projection failure sets all three maps (`visible`, `caches`, `editorTextByField`) to NULL. A profile-denied row whose projection is proved may retain the maps for inspection, with every field capability false. A matched saved header with no incoming rows is valid: it renders a specific empty message and no row/field editor. The existing saved reader also verifies its incoming provenance count against the line array, so omitted rows are not treated as a valid empty document. Recovery details use `eventIndex`, `fieldId`, `editorText`, optional baseline/preview, and diagnostics; failed results never replace the client's accepted preview. These structural requirements were coordinated with both owners, rather than inferred from legacy endpoints.

## 3. Explicit committed-field interaction

Use a separate section headed **Calculation preview** with the persistent explanation: “Preview one saved item's calculation. Saved return amounts are unchanged.” Do not label its controls Save, Apply to return, Update return or complete invoice. Retain the saved incoming/outgoing amount summary outside the preview and label preview results separately.

The first bounded UI uses one saved-row selector, one allowed-field selector and one exact-text editor. An explicit **Preview field change** button (or Enter in that editor) simulates one completed desktop LeaveCell. Each deliberate action appends one event, including the same text/value as a previous event. No automatic change/blur submission, sorting, value-diff deduplication or local arithmetic occurs. This is deliberately a completed-cell simulation, not a claim that every desktop grid keyboard action has been ported. Ordinary Tab moves focus without committing. Focus alone never calculates.

Select the source editor text from server `editorTextByField` on opening/changing a field. The desktop EnterCell presents two decimals for these fields (TR_SALE_RTN.cs 4538–4541, 4561–4575), limits text to ten characters and selects the text (4588). The visible labour percentage can become three decimals in the manual-total branch (5115); copying it verbatim into a re-entered editor would be wrong. Server editor text therefore remains separate from visible strings, raw values and comparison caches. Do not truncate a large saved value merely to fit maxLength or deny the field solely because the loaded text is longer than ten characters. Preserve the full server-derived editor string; an unchanged oversized commit fails client input validation and retains it, while the operator may deliberately replace it with an accepted shorter value. This ten-character HTTP profile bound does not prove a desktop prohibition: source programmatic Text assignment may exceed the control MaxLength.

Keep the selected field locked while its editor contains an unpreviewed entry; provide **Discard field entry** to restore its server-derived presentation. Keep row selection locked once there is an entry or journal; provide explicit **Discard preview and close** or saved reload. This prevents silent loss or rebasing of a draft onto another row.

Serialize explicit preview requests: while one is in flight, disable the editor and selectors. The next event starts from the last returned preview presentation, while POST always replays the complete journal from the observed saved baseline. On a response, replace only transient preview visible/caches/editor presentation and accepted events. Retain the same saved raw object, metadata draft, complete row identity and baseline.

The first twelve fields are money/labour/discount/tax LeaveCell cases at 4592–4664. Width zero/unresolved and denied fields are not editable. Resolve this from field capabilities and authoritative source-column configuration, never CSS width or whether an input is visually present. Control characters U+0000–001F/U+007F are refused by the transport profile even where the pure kernel's whitespace parser would accept them. Product, source F1, labour-code selection, gross Enter/component grid, tag generation, row insertion/reordering/deletion and child commits have no controls in this slice.

## 4. Recoverable state and asynchronous authority

Maintain separate immutable observations: loaded saved document; trusted replay bootstrap; current selected-row baseline; accepted ordered journal and preview; current editor entry; and error/reload state. Each async token binds a monotonically increasing panel generation, complete scope/document identity, operation sequence and selected row. Scope transitions A→B→A, document reload with the same business version, explicit close, row changes and a new bootstrap invalidate old tokens. A stale success, rejection or finally handler cannot publish a result, erase a newer entry, clear a newer busy state or restore old-scope controls.

On 422 or client input validation failure, keep the entered text and prior accepted preview. Do not append a rejected event to the accepted journal; display the attempted event/index separately and let the user correct the same field. No later event is accepted while that attempt is pending, so there is no hidden reordering of a failed prefix. An explicit empty/whitespace completed event retains its original text and uses the source kernel's blank-as-zero rule; opening an empty editor alone never commits it. Surrounding whitespace on a plain decimal is retained. Non-decimal/localized/oversized text is rejected rather than coerced.

On 409 preserve accepted journal and current entry, mark results stale and block another commit. Offer explicit **Reload saved return and discard preview**. Reload first obtains an authoritative saved document; reopening preview obtains a fresh trusted state. Do not automatically replay a retained old journal under changed settings, masters or saved rows. Likewise 401/403/404, an unreadable response, and uncertain network/5xx outcomes require explicit reload before resumption. Since POST is nonpersisting, these outcomes never imply a financial commit; preserving the entry and requiring deliberate reload is a client recovery rule.

Failed bootstrap means no token and no editable controls. Unsupported rows and capability reasons remain visible. Fresh View may allow preview even when metadata edit rights are absent; do not derive `canPreview` from the metadata `canUpdate` flag. Preview cannot acquire numeric write permission.

## 5. Presentation and accessibility

Use business labels and saved SR/OLD/instance/item identity in context. Display the selected field's configured caption, original source caption where useful, and the exact saved baseline/current preview strings. A readable table compares all returned visible calculation values without replacing the saved amounts. Keep the existing exact saved raw details available. Calculation tokens and caches remain in the API/evidence, without adding their JSON to the operator flow.

No nested forms. Buttons are `type="button"`; editor handles Enter locally with default prevented. No Ctrl/Cmd+Enter route to the metadata or hidden legacy Save. No new F1 binding or invented desktop shortcut. Each selector/input has a visible label, status uses `role="status"`, errors use `role="alert"`, and blocked reason is associated with its field. Horizontal table overflow is contained in the panel. After an explicit preview response, return focus to the same editor; after close, return it to the opening button. Focus restoration also checks the current request generation.

`aggregateRequired` means desktop row calculation would next invoke aggregate callbacks at 5157–5158. It does **not** mean this preview recalculated the header, outgoing leg, payment/refund, tax ledger or reports. Show a clear row-only note rather than a misleading voucher total.

## 6. Required checks

1. Strict observation readers: exact scope/voucher/document/config versions, full six-field identity matching saved raw, duplicate/missing rows, opaque token shape, false numeric-save capability, numeric-keyed string values/caches and authoritative caption/field IDs. Malformed observations never enable editing.
2. Exact ordered payload: rate→manual amount versus reverse, repeated identical commits retained, no unrequested properties, no Number conversion, no snapshots/policy/caches echoed. Empty baseline never runs calculations.
3. Source editor formatting: server two-decimal text differs from visible three-decimal labour percentage without changing raw/visible on focus. Ten-character typed limit does not truncate loaded data.
4. Recovery: invalid/422 draft retained, prior preview unchanged, rejected attempt not accepted; stale409 and network/5xx retain draft but require explicit reload; failed load leaves no token. No automatic resend, reload or rebase.
5. Lifecycle: delayed scope/document A→B→A, same-version parent rehydrate, close while loading, stale error/finally, two exact noncontiguous rows and duplicate voucher across configured books. Metadata controls never write while preview active.
6. Real browser: fresh simple P/I untagged incoming-only fixture, SR17/42 and OLD31/58, explicit finite non-NULL canonical amounts, no outgoing/BAR/DM companions. Cover ordered explicit commits and same-value event, invalid draft, true second-client document/config stale conflict, deliberate reload, no numeric persistence, keyboard/labels/focus and responsive table bounds. Existing Round6 companion/NULL/huge-value fixture remains read-only if ineligible; do not weaken eligibility to reuse it.
7. Service/HTTP owners prove read-only database write sets and fresh permissions. UI journey inspects actual request paths/bodies and unchanged saved values; it cannot alone prove every table stayed unchanged. Root runs coordinated full tests/build/browser after product/test freeze.

The delivered scope may be called “trusted saved-row calculation preview” after verification. Complete desktop Return transfer still requires source admission, all grid workflows, aggregate/payment accounting, numeric persistence, stock ownership, reversal, printing/reporting and business acceptance.
