## Reviewed authority and write boundary

`saleReturnIncomingReplay.ts` requires complete explicit scope and an exact nonzero five-digit voucher key. Its POST input parser admits only `replayVersion`, `rowIdentity` and an ordered array of zero to 100 `{fieldId,editorText}` events. It rejects extra snapshot/policy/context/source properties and malformed tokens. The twelve admitted money/labour/discount/tax fields are identified by source column IDs, not captions. Known but unsupported source/hidden fields return a refusal instead of invoking admission. Original editor text is retained; repeated same-valued events are not deduplicated.

GET and POST compose `readSavedSaleReturnIncomingTx`, `readSaleReturnIncomingConfigurationTx` and relevant item-master observations inside the same tenant-bound RepeatableRead transaction. Both new helpers only perform the pre-existing reader/snapshot work on the supplied transaction. The inspected path contains no Return writer, metadata writer, allocator, sequence, stock update, ledger posting or `$executeRaw` business mutation. Reading an observation is not a row reservation or a numeric-save capability.

The composite token includes full scope/voucher, document version, configuration version, projection/profile/contract versions, field IDs, and raw/physical master observations. The saved document token includes both document legs and observed companions. Current master inputs are correctly added because the older metadata token intentionally omitted item names. Present-row revision/locator changes invalidate tokens. A consistent snapshot is as of database observation, not necessarily latest at response delivery. Absent→insert→delete history is not guaranteed to change a token after all observed rows are restored; no durable-history claim is made.

POST rebuilds the current observation and compares the composite token before applying a journal. It resolves the exact saved row token, requires fresh profile/field capability, builds event context and widths from the server, and starts each request from its saved baseline. It never trusts a previously returned preview as request authority. A rejected calculation reports its failed index/text and prior accepted-prefix snapshot; it does not return a successful partial result. Every successful response binds scope, voucher, versions, row and exact event sequence and returns `canSaveNumeric:false`.

The root routes require only the four explicit query scope keys, use `no-store`, and map typed errors with `{error,message,details?}`. `routePolicy.ts` assigns both routes to `Sales/Sales Return`; the POST is explicitly a read action. Existing central middleware loads current principal/owning form rights on each request and validates the selected business scope. Thus View-only simulation does not acquire Edit, stock or financial write rights. Unknown errors remain observable through the existing error boundary.

## Source correctness and contained profiles

Primary `TR_SALE_RTN.cs:10353–10438` loads saved rows in numeric `SR_NO` order and displays ordinal `i+1` separately from persisted SR/OLD/instance identity. Loaded decimals must be formatted before seeding the eight caches; no row calculation occurs at load (10447 invokes the aggregate-fill method). The new API passes server raw rows to the dedicated projection. It retains exact raw fields and separate visible/caches, including raw NULLs and six-digit timestamp text. Whole-row numeric-NULL/malformed/precision refusals remain explicit initial-profile constraints.

The source query's `A.*` and additional master `RATE_TYPE`/`IT_TYPE` columns have an unresolved duplicate-name binding. Exact saved/master agreement is required; the API does not assume the current master overrides persisted types. It retains all discovered duplicate/collation-alias candidates for projection refusal and token construction. Exact missing/duplicate/source-inconsistent masters are not silently collapsed.

The initial supported state is deliberately narrower than all desktop Returns: incoming P/I, ordinary untagged N/empty, no active approval/employee issue flags, no outgoing leg or BAR parent/component/DM companions, existing saved date/period/document eligibility. A BAR header must match the previously proven source metadata shape. These are rollout constraints for a nonpersisting row preview, not invented fiscal, tag or refund rules. The service observes other finance/stock rows and leaves them unchanged.

The twelve committed fields use authoritative configured nonzero widths; hidden/unresolved fields are refused. Configured Fine width drives the existing F calculation branch, not current numeric content or CSS. Source F1/LCode/TgLCode/gross-entry/admission and hidden events remain inaccessible. The frozen mathematical Decimal profile does not establish universal VB Double/Format/culture, DBNull, large-value or alternate-edition equivalence.

Literal cache resets distinguish `"0"` from `"0.00"`; expected raw values remain independent of formatted display. The final passing service tests use real server tokens and compare all63 visible values plus all8 caches at each of the six prefixes, exact original returned event sequences, aggregateRequired and canSaveNumeric:false.
