## What the tests prove

The service tests assert complete v1 DTO/token equality before and after new v2 reads/previews, exact raw header values (including large unrelated decimal, NULL, blank and microseconds), all14 participating aggregate columns, all eight selected-row comparison caches, all71 blank loaded aggregate cells, source bill labels and the final ordered event list. Empty journals preserve the opened phase without applying a row event; same-value and repeated events retain their order. Selecting the second parent still aggregates both parents. Whole-header raw values remain unchanged even when displayed bill values differ.

Every request uses the full selected tenant/company/location/year/configured-book/voucher identity. The outer v2 token binds raw and physical observations; tests change header data, tax settings, a same-value tax row revision, an unselected item's master, tax labels and bank labels. Stale versions fail before either row/header projection or replay (call-count spies observe real functions without replacing implementations). A real RepeatableRead test performs an independent owner-client update between actual SQL observations; the in-flight result stays on its original snapshot while the next request observes the changed version. No SQL, HTTP, authentication, projection or calculation response is mocked.

The authenticated tests use actual Fastify routes, password hashing, cookies and fresh owning-form View rights with Edit disabled. Both GET and nonpersisting POST work for that role, return no-store, and fail after rights are revoked. Wrong selected scope is the existing exact409 `scope-mismatch`; missing fields, arrays, unknown query authority and malformed tokens are contained. All12 admitted field IDs are exercised with original same-value text. Client policy, bill phases, ledger mode, source references, whole rows and event context are rejected. Hidden supported columns remain422; unknown IDs and printable-ASCII violations (U+2028, NBSP, terminal U+2028 in editor text or field ID) are400.

The ready profile refuses partial bills: an unselected unsupported numeric row, tagged sibling, outgoing parent, empty voucher, invalid direct-Val header NULL, negative unsupported tax precision or ambiguous company settings cannot silently yield an authoritative subset. Missing/duplicate tax labels and duplicate/case-alias bank masters produce visible unresolved labels without replacing saved numeric tax values with current master rates. SQL NULL TAX_ROF follows the explicit Fnv zero path. Posting-book DATA_TYPE and an unrelated earlier customer ledger amount never manufacture a ledger-mode decision: closing remains unavailable with null amount while known bill values calculate.

Before and after successful and refused requests, tests compare all raw rows plus xmin/ctid in27 business/configuration/master/counter tables for both fixture tenants. The authenticated session/audit infrastructure is outside this business snapshot; login activity is not misrepresented as globally write-free. Supported request effects are transient responses only.
