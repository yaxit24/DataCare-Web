# X13 round7 original-sale read implementation

Implemented the bounded [original-sale selection contract](x13-original-sale-selection-contract.md) in `web/apps/api/src/modules/sales/saleReturnSource.ts`, with dedicated service tests in `web/apps/api/test/saleReturnSource.db.test.ts`. This is a **read-only source observation slice**. It does not implement an operator F1 dialog, apply a source into an incoming draft, calculate Return totals, admit/reassign tags, or change any existing Return writer.

The service exports `listSaleReturnSourceVouchers` and `getSaleReturnSourceItems`. Root owns route/RBAC integration and authenticated HTTP tests. Both functions require a complete target Return scope. Source company/location stay equal to that target, while original year/book/voucher are explicit separate fields. Active configured SALES source books and unique configured original and target years are required. Historical configured years are supported. Exact saved voucher keys are tried first; only an absent short numeric key falls back to five-digit padding, allowing imported6–8 digit keys and coexisting1/00001.

The detail DTO carries separate `scope` and `source`, a SHA-256 observation version, complete raw header/parents/children, immutable original parent references, resolved children, separately preserved unresolved components and linked Return evidence. All raw PostgreSQL scalar values become text before JSON enters JavaScript, including NULL, blanks, whitespace, decimal scale and microsecond timestamps. Physical IDs are represented through scoped opaque record identifiers and internal version inputs. No supplied reference, raw value or availability flag is a write authority; `capabilities.canApplyIncoming` is always false.

Child ownership follows the primary Sales writer's **SL_IDTL.SR_NO → parent OLD_SRNO** relationship, corroborated against saved tag/instance where present. Conflicting tags/instances, duplicate old keys/child identities and orphan components remain visible. A malformed legacy web pointer is not repaired by a tag-only guess. Parent and component output uses SQL numeric SR_NO/ISR_NO order with a physical-row tie break; tests deliberately insert children10/9/3/2 and expect2/3/9/10. Source values remain unmodified.

Linked Return evidence spans Return years/books under the same original year/book/voucher. A known different original location is excluded. Whitespace-padded references are discovered by normalized comparison but retained raw and classified ambiguous; incomplete location, orphan header, duplicate header and NULL/blank linked tags also produce ambiguity. A NULL in the desktop's tag NOT IN relationship never silently empties the displayed source rows. Matching prior tags are marked returned. These statuses describe inspectable source candidates, not available stock or safe Return admission.

Missing/duplicate/blank item codes produce a separate diagnostic, without resolving an empty master or borrowing another company's name. The source observation includes relevant original/target year and book configuration, item masters, source physical/raw rows and linked Return observations. Source row edits, physical delete/recreate, A→B→A, changed children, linked Returns and relevant master/configuration changes invalidate that observation.
