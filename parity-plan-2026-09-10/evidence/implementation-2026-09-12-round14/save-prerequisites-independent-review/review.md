## Header exact-binary64 boundary

The three targets are Float at schema5708/5709/5714. Desktop Save reads nAcCrAmt for RTN_NET_AMT (12707), MSG2_TOTAL[3,3] for RTN_TOT_AMT (12789), and MSG2_TOTAL[8,3] for RTN_BILL_OS (12809). The qualifier accepts exactly those three own string properties and returns no partial candidate values when any one fails. It does not verify that a candidate came from those source states.

The mathematical algorithm is sound within its declared input domain. A canonical decimal is an integer n divided by10^s. It has finite binary expansion exactly when5^s divides n. Dividing those factors out leaves a power-of-two denominator; removing numerator factors of two yields an odd significand times2^e. At most53 significand bits and a valid binary exponent are necessary and sufficient for exact binary64. Zero and sign do not change that criterion. The code uses bounded BigInt arithmetic throughout (39–53), so it does not silently accept the decimal rendering of a rounded Number.

I manually reviewed all28 literal distinctions: zero/negative-zero/ordinary spaces and plus normalize exactly; 0.5,1.25,-0.125 are dyadic; 2^53-1,2^53,2^53+2 and2^64 are exact, while the adjacent odd integers above2^53 are not. The small dyadic0.000003814697265625 is2^-18; 0.00000095367431640625 is2^-20 but its20 decimal places intentionally exceed this profile. Decimal±0.1 and1e-18 retain a denominator factor5;1.000000000000000001 and2.0000000000000004 do too. The latter is not the exact rational value of the nearby display-rounded Double. The1e36 boundary, exponent text, newline, blank, NaN, Infinity and repeated sign are refused for their separately declared reason. `+.5` and `1.` are supported plain forms.

The public18-decimal-place and1e36 limits already constrain ready nonzero values to normal finite binary64 magnitudes. The -1074/1023 guards are mathematically correct but do not establish tested subnormal/extreme-exponent support under this input grammar. This is deliberately narrower than normal decimal-to-nearest-Double conversion: ordinary decimal cents such as0.01 may map to a row candidate yet fail header exactness. Conversely2^64 may qualify as an exact Float while exceeding a numeric(18,2) ledger/row field. Any future writer must intersect every field's actual storage qualification.

The initial terminal-separator defect claim was withdrawn as described above. The persisted source snapshot in this review is already after root's ASCII guard strengthening and claims no hash for the earlier bytes. Its precheck rejects non-ASCII characters before regex matching; root's new tests include U+2028, U+2029 and NBSP. Those cases express the intended boundary, but do not demonstrate that the prior non-multiline grammar admitted such values. The observation and additive case files preserve that attribution limit without retroactive execution credit.
