# Option A finite financial effect planner — proposed pure contract

This new internal diagnostic module plans the seven already-present conditional T-book financial rows. It never performs DML or grants admission. `canCommit` is always false, including `status:'ready'`. Its supplied observations, qualifiers, identities and hashes do not authenticate facts, prove completeness or replace a trusted transaction. No current preview/metadata capability changes.

`planSaleReturnFinancialEffects(input: unknown): SaleReturnFinancialEffectsResult`, constants `SALE_RETURN_FINANCIAL_EFFECTS_VERSION='primary-return-seven-financial-effects-v1'` and `SALE_RETURN_FINANCIAL_EFFECTS_PROFILE='saved-one-pi-n-sr1-c27-t-zero-tax-existing-effects-v1'`.

Exact input envelope: `{tenantId,rowIdentity,documentVersion,context,before:{incoming,header},after:{incoming,header},observed:{acData,rojMel,mainStock,taxData}}`. Identities/versions are retained strings; hashes are 64 lowercase hex. Each phase is complete current-schema SQL-style raw string/NULL maps (incoming79/header102 fields). Every unowned field and key must remain byte-identical between phases. Only incoming OTH_AMT/TOT_AMT/NET_AMT and header RTN_NET_AMT/RTN_TOT_AMT/RTN_BILL_OS may change. The selected row is stable primary P/incoming I, N, SR1/OLD1 with nonzero instance. This module does not calculate those fields or prove a c27 journal produced them. Row NET and whole-unit rounded header NET are distinct: Other0.49 may yield row110.49/header110; no row/header equality shortcut is permitted.

Context is `{status:'unavailable',reason}` or `{status:'qualified',observationIdentity,companyShortName,openingDate,book,bookDetail,item,group,account,taxes,storage}`. Book/bookDetail/item/group/account are one-element arrays and taxes is a two-element array. All selected master maps are exact relevant-field maps, not arbitrary echo payloads; selected cardinalities are one book/detail/item/group/account and exactly two tax records. Every company/location/book/item/group/account/tax join is compared explicitly. Book and detail remain distinct authorities for short name and DATA_TYPE, with canonical SALES RETURNE, I, T, SL_DATA and detailSR1. Account GST type is literal N, account is not00045, company is explicitly non-UAE, and date is on/after a canonical supplied opening day. Canonical master codes are not silently trimmed, case-folded or alias-selected. Completeness of the selected catalogue and other write dependencies remains an external prerequisite.

Storage supplies explicit qualified target strings for AC timestamp ENTRY_TIME, stock date ENTRY_TIME, stock text STK_DATE, exact two STR-dependent AC keys, stock text ITM_DISC and tax text ZERO_RATED_AMT. The exact storage subobject is `{status:'qualified',observationIdentity,values:{acEntryTime,stockEntryDate,stockDateText,customerLedgerKey,saleLedgerKey,stockDiscountText,taxZeroRatedText}}`; unavailable remains explicit. The initial current-PG text profile requires ISO stock date and literal zero text, separately witnessed; this is not Windows implicit cast parity. The planner neither invokes Windows conversions nor invents clock/user/SQL STR formatting. A context qualifier is an independently supplied precondition, not evidence of original-runtime equivalence. Rojmel keys use exact source concatenation with suffix01/02. Raw source date/clock and metadata remain inspectable. Mapped fields are checked against current Prisma target length/type/precision; numeric fields use exact decimal mathematics without Number conversion. Unowned Float raw values are retained without pretending they are newly synthesized exact-binary64 values; mapped Float values must compare to the retained observation and receive no patch.

Observed effects require exact 2 AC,2 Rojmel,1 stock,2 tax membership. Each observation is `{physicalIdentity,version,raw}`. AC/stock/tax physicalIdentity is canonical positive row_id; Rojmel is its exact LEDR_KEY (no invented row_id). Raw maps require all current table fields, including tenant/physical keys and unowned schema columns; bounded plain string/NULL future columns are retained as opaque unowned data. Roles are identified by exact expected keys/stockSR2+ISR1/taxSR1/2, never array order. Duplicate, missing, extra or wrong-scope rows refuse. Unknown extra envelope fields refuse; bounded raw extension columns are preserved. Numeric raw scales are preserved if mathematically equal and target-representable; source text/NULL must match exactly. Unsupported changes to source-owned fields refuse; schema-unowned raw values are copied exactly.

Projection returns every source-owned field for each role, 29+29+34+34+49+23+23=221 entries per phase. Role order follows Save callbacks: two AC, two Rojmel, stock, two tax (`TR_SALE_RTN:13411,13423,13435,13447`). Only AC customerCR/saleDR, Rojmel outstandingCR/summaryDR, stockOTH/NET and taxNET/TOT may appear in patches. No-op yields seven empty patches and unchanged candidate raw. Any refusal returns `candidatePlan:null`; independently valid projections/raw observations remain inspectable. Returned plain data is detached and deeply frozen.

Source expressions: `Ac_Ledr.SaleReturn_Ledr:1324,1326`; `Ac_Rojmel.SaleReturn_RojMel:586,588`; `Ac_Stock.SaleReturn_Stk:247`; `Ac_Tax.Sales_Rtn_GST:191,193`. Literal N is nonblank and does not prove BAR absence. No children, outgoing, BAR/temp/remark/audit changes or external-reference admission is inferred. Zero tax/tenders, positive return amounts, RATE_UNFIX=N and positive retained metal amount are explicit finite-profile facts. Null operands of SQL predicates never become zero or truthy. Row/header storage qualification, complete replay, N companions, USER_UPDATE ordinary permission, all Save guards, edition-E audit, closing/provider/clock/key authority, external references and atomic Serializable write/postconditions remain required before a writer.

Fixture expected full maps must be frozen before implementation. Fixtures are mathematical supplied-observation cases, not executed database/hydration or original-Windows acceptance. Scoped integration commands will be recorded after source/test freeze; no active export or schema edit belongs to this stage.
