# Saved Return effect context: finite SR1 observation profile

This new staged pure prerequisite qualifies supplied observations for the first saved primary incoming c27 profile. It is not an API, database reader, admission check or writer. `canCommit:false` always. Round14/checkpoint41 and all active source remain unchanged.

`projectSavedSaleReturnEffectContext(unknown)` is exported from new `saleReturnEffectContext.ts`, with version `saved-sale-return-effect-context-v1` and profile `canonical-pg-preserved-sr1-effect-context-v1`. Input is exactly `{header,incoming,storageText,provenance}`. Header allows only optional VCH_DATE/VCH_TIME; incoming allows only optional CO_CODE/LC_CODE/CO_YEAR/CO_BOOK/VCH_NO/SR_NO/VCH_DATE/VCH_TIME; storageText allows only optional stockDateText/stockDiscountText/taxZeroRatedText. Each observed scalar is string or SQL NULL. Missing is preserved separately. Provenance has exactly documentIdentity/documentVersion/rowIdentity/observationIdentity, opaque nonblank printable ASCII identifiers, max256 with no outer whitespace. Exact own enumerable data-property envelopes exclude arrays, exotic prototypes, accessors, symbols and extra keys. Malformed shape is invalid-input with no retained observation; well-shaped unsupported raw values remain detached and immutable.

Result is `{version,profile,status,canCommit:false,observation,storage,diagnostics,requirements}`. Ready storage is exactly `{status:'qualified',observationIdentity,values:{acEntryTime,stockEntryDate,stockDateText,customerLedgerKey,saleLedgerKey,stockDiscountText,taxZeroRatedText}}`. Unsupported/invalid storage is null. Observation retains the complete bounded input exactly; it does not replace the full business/physical snapshot required from a future server reader. No supplied identifier, version or status string authenticates itself.

The existing saved clock helper is reused unchanged. Primary TR_SALE_RTN10104–10106 loads header date and formats HH:mm:ss; Save assigns header VCH_DATE/VCH_TIME12607/12885, incoming14279/14557, BAR header13100/13108 and BAR parent13928/13932/14115. This stricter edit profile requires header and line dates to agree, each timestamp day to agree with its date, both whole-second times to agree, and every supplied fractional digit to be zero. It refuses nonzero microseconds rather than silently drop persisted precision. Zero-fraction spelling remains retained in observation; output acEntryTime uses canonical JSONB T form without fraction. No timezone/JavaScript Date is used; the existing clock helper validates the Gregorian calendar. Local DST-looking clocks are observations, not resolved instants. Source Windows locale, original target date range, DataAdapter conversions and provider behavior remain unproved.

Ac_Ledr1324/1326 concatenate the exact line scope followed by role01/02 and SQL STR(A.SR_NO). The current profile admits only exact raw serial `1`; its STR result is **nine spaces followed by 1**, total10 characters. No Number conversion, rounding, padding/truncation of scope segments, float exponent handling or general STR implementation is introduced. SQL STR's documented defaults are width10 and zero decimal places; right justification of exact1 requires no rounding ([Microsoft documentation](https://learn.microsoft.com/en-us/sql/t-sql/functions/str-transact-sql?view=sql-server-ver17)). Fractions, signs, leading zeros, other serials and overflow are unsupported, even where SQL Server could produce a string. Observed company/location/book use nonempty uppercase ASCII alphanumeric values within current widths2/2/3; year uses uppercase alphanumeric/hyphen within10; voucher uses exact5 ASCII digits. These are explicit transport/storage profile bounds, not auth/company/calendar rules. Scope is concatenated unchanged, then target key length is checked against varchar50. Maximum admitted key length is34; no generic Rojmel helper (which pads/truncates) is reused. Rojmel source586/588 suffix01/02 is handled independently by the financial planner without STR.

Ac_Ledr takes AC_DATA.ENTRY_TIME from incoming A.VCH_TIME; Ac_Stock247 takes MAIN_STOCK.ENTRY_TIME from the same expression, and STK_DATE from A.VCH_DATE. Current schema makes AC ENTRY_TIME timestamp(6), stock ENTRY_TIME date, and stock STK_DATE varchar255. Thus output acEntryTime is the qualified local timestamp and stockEntryDate the exact coherent day. Source stock ITM_DISC and tax ZERO_RATED_AMT use numeric zero but current targets are varchar255.

**Root-approved current-PG preservation adaptation:** source SQL Server's implicit date→text/culture spelling is not established. The helper requires explicit observed stockDateText equal to the ISO incoming date, and both zero-text witnesses equal to literal `0`. It preserves these witnessed strings and refuses NULL, absence, equivalent numeric spellings, locale dates or any other text; it does not manufacture them. This proves equality within a named current-storage profile only. Future server hydration must bind each witness to exact full raw/physical effect rows in the same transaction, including both tax rows, and refuse inconsistent witnesses/membership. A caller's fabricated witness is not trusted merely because this function accepts it. Source equivalence for arbitrary Windows/SQL Server implicit casts is not claimed.

BAR clock/text context is still external: this helper establishes a coherent common date/time, but neither observes BAR membership nor builds its other context fields. The existing complete BAR matcher and a trusted typed observation adapter must compare the source-shaped parent/header and preserve raw values. A ready storage qualifier does not prove all companion clocks/text aliases, SQL Server collations, identity uniqueness, guards, stock availability, ledger mode, closing balance, full effect membership, or financial totals. All admission and source branch requirements from the frozen effect inventory remain required.

The 60 full literal cases were frozen before implementation (fixture-freeze.json). Focused pure tests will additionally cover malformed descriptor envelopes, retained NULL/absence, full detachment/freezing and no authority. No database execution is part of this stage. **Post-integration independent database type/readback tests remain required** for actual JSONB strings, date/timestamp parameter behavior, exact 33/34-character ledger keys including spaces, zero text witnesses, BAR clock coherence, and physical no-write snapshots. This stage gives no PostgreSQL execution or SQL Server runtime acceptance credit.
