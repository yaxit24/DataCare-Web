## Bounded API contract

Existing URLs and principal form mapping remain: GET/POST/PUT/DELETE `/masters/styles`, GET `/masters/styles/meta`, POST `/masters/styles/import`. The fresh owning permission is `Masters/Styles / Columns`. Inherited web authorization permits create when view is granted; edit/delete require their corresponding rights. This retained mapping is not a claim that the complete desktop UT_SETTING permission model has been ported.

Meta reports the exact three key columns and fresh `capabilities: {canCreate,canUpdate,canDelete}`. List and meta are `Cache-Control: no-store`.

- POST accepts the three key fields (CO_CODE can be omitted and is filled from authenticated company) plus only supplied COL_NEW_NAME/COL_RPT/YES_NO. Existing same full key is 409. Same original heading in another family is independent.
- PUT requires the full original key, a valid observed `version`, and at least one mutable field. Omitted values stay untouched, including saved NULL, blank, and historical flag values. Explicit empty string clears text; explicit NULL remains an explicit supported API value. No surrogate/tenant/version fields are SET.
- DELETE requires full original key and version, and accepts no mutable fields.
- Service-level missing/invalid key, unknown properties, foreign company, missing/malformed version, and unsupported new flag spellings are 400. The shared authenticated HTTP scope guard runs first and retains its existing 409 for a request company/location/year that conflicts with the session; this is distinct from the domain validator. Missing saved key is 404. Stale physical observation, duplicate identity, and duplicate create are 409. The browser requires deliberate reload after 403/404/409, network errors, or HTTP5xx; validation400 remains recoverable in the current draft.
- BOOK_NAME/COL_NAME remain case-sensitive exact strings. Internal spaces are retained. Empty, outer whitespace, or control-character identities are readable but cannot be mutated through this endpoint; imported reconciliation is an explicit separate task. Neither server nor client silently trims or renames them.
- Changed flag values allow Y/N/blank/NULL. An unchanged imported unusual spelling may remain untouched or exactly repeated; this does not normalize it into a new source branch.

The observed row version hashes tenant/company, complete key, physical row ID, xmin/ctid, and all six business values. Updates/deletes lock the exact key and compare the token before mutation. A per-tenant/company/family/name advisory lock serializes this **generic CRUD and generic CSV create path**, including simultaneous absent creates. It does not cover company cloning, restore, administrator SQL, or any independent writer. Existing duplicate physical rows remain readable and are refused before any write, even when values are identical. There is no new global unique constraint and no universal multi-writer serializability claim.

CSV import keeps the previous `{rows}` request and `{created,failed,errors}` result, creating each row through the same complete identity validation. It is per-row, not an atomic entire-file import. The dedicated parser accepts quoted commas/newlines/quotes and BOM before quoted headers, validates each row's shape, and discards only recognized prior export observation/surrogate metadata. Export names all six business fields and explicitly exports **loaded rows**. CSV's existing NULL-to-blank encoding is visible in the UI and remains a historical-data round-trip limitation; JSON observations/partial edits preserve NULL separately.

## Paging and observation safety

GET remains an array for compatibility. Optional `offset`, `limit`, exact `family`, and literal case-insensitive `search` are Styles-only. Default limit 100, maximum 500; the dedicated page uses 50. Offset is bounded to 0..1,000,000, so installations exceeding that operational bound need a separate cursor extension. Search treats `%`, `_`, and backslash literally. Order is family, original name, then numeric physical row ID; null imported keys stay readable.

Each row contains six business fields, row_id as text, `_columnVersion`, `_columnIdentityCount`, `_columnCollectionVersion`, and `_columnTotal`. The ambiguity count is computed before family/caption/search filtering; searching for just one duplicate's caption cannot make that identity safe to edit. Total is the filtered count. PostgreSQL metadata aliases are quoted to preserve the promised camelCase keys.

A Repeatable Read snapshot gathers the company physical revision inventory and the bounded list page. The collection token includes tenant/company, filters, and present-row revisions. Page append requires the same token and total, nonempty continuation, and distinct physical row IDs. An observed insert/delete, any extant row edit, or present-row ABA causes reload rather than mixed pages. This is not a durable mutation journal: an absent→insert→delete history that restores the exact empty/current set is not remembered, and a vacated arbitrary offset returns an empty legacy array rather than a separate collection envelope.

After mutation, import, reload, filter change, or scope change the page starts again at offset 0. Exact-family input reaches a later family without needing that family's name on the first page; its datalist is only a convenience. Load more reaches subsequent pages within the documented offset bound. No silently truncated first 100 list remains.

## Client saved identity and recovery

The dedicated static Styles route replaces only this master's dynamic generic page. Other master engines/pages remain untouched. The editor separates original identity from mutable caption/visibility/repeat controls. Saved family/name are read-only; partial patches are generated from touched controls, so a blank input displayed for saved NULL does not erase it unless deliberately edited. Invalid or ambiguous imported rows show a reconciliation reason and disabled mutation buttons. No DESIGN/STYLE_CODE image editor is rendered for COL_MAST, which has no such source identity.

Every request includes selected company/location/year explicitly, while storage identity remains company-wide as in the source. A complete scope-keyed remount and an alive/request-generation guard invalidate old loads, file reads, mutations, and readbacks; render-time filter identity also disables old observations before the next effect commits. Actual Shell scope changes reload the page. These safeguards do not grant scope permission; central server session matching and fresh form authorization still enforce each request.

Conflict/uncertain outcome retains the draft, disables mutation, and requires the explicit **Discard draft and reload** action. No upload-style automatic retry or silent PUT resend occurs. After an acknowledged mutation the prior selected version is invalidated before reading authoritative settings. A failed readback reports the change as saved with refresh required and does not offer to replay the committed mutation. Reload observes fresh rights and values. A saved row deleted elsewhere or newly revoked edit right also requires reload.
