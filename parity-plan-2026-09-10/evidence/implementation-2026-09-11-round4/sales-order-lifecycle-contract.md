## Operator lifecycle and state boundaries

1. Select a configured ordinary Sales book. The editor is disabled until its scoped calculation settings load. A failed configuration request displays the diagnostic and Retry order settings. Save also checks readiness independently of the controls.
2. Choose the order date and customer; enter parent and component values. Numeric edits remain drafts until actual blur events. Invalid numeric drafts remain visible and fail validation without replacing neighboring rows.
3. Save creates the order in the complete selected scope. Successful save clears the entire editor. The returned voucher number is used for later load; the browser does not assume it is the first voucher in a book.
4. Load by visible voucher number or select a recent order. A new load clears the previous saved selection before requesting data, including on not-found or failed load. Scope and request-generation checks suppress stale responses.
5. Reopening preserves parent SR_NO and child ISR_NO, including imported gaps. Stable client keys prevent the active Design picker or image row from attaching to another parent after UI reorder. New serials advance from the loaded high-water marks. Removing a saved row is explicit; clearing its item code cannot silently delete it during serialization.
6. Replacement includes expectedVersion and all remaining parent/child values. Header, parent and component dirtyFields convey explicit zero/clear intent; hidden unchanged fields are retained. A conflict retains the operator draft for review and explicit reload.
7. Saved image actions use the actual loaded parent identity/version. A newly appended unsaved parent cannot reuse another saved row's image identity. Design selection preview is independently scoped to source, current row and current item. A selected source with NULL image is normalized to an explicit empty image identity and shows the absent-image state. When a draft Design number/image identity differs from the persisted parent, old saved photo/actions are suspended immediately and a save/reload notice is shown; unchanged saved metadata keeps normal image actions.
8. Delete asks for confirmation and sends the loaded version and full scope. Its continuation checks the scope again. The API deliberately changes the version when it replaces rows, even if every business field is identical, so no-op verification compares all business fields and separately checks that the old token is invalidated. Server consumed/allocation guards remain authoritative; blocked documents are shown as read-only.

## Calculation and Design event protocol

The new frontend helper keeps visible values, the last calculated fine/metal/net values, and hidden labour cache84/85/86 separately. New rows begin with zero cached calculations. Saved rows hydrate their persisted amounts and cache from the source-shaped read DTO.

`orderEdits` records actual events in order: text field commits, numeric blur commits, labour commits, resolved Design source selection and explicit clear. New rows begin with the known zero/text baseline. Payloads containing this journal omit the legacy labourEdits/action protocol. Journal-affected text fields are sent explicitly even when empty, so selecting a source with no image or size clears the previous source value instead of being confused with an omitted field. Untouched loaded rows have no journal and retain original business values. Server replay resolves Design source data itself and compares the resulting writable values; client computed totals are not authoritative.

The separate last-calculation basis also retains imported fine/metal amounts when an unrelated amount trigger leaves the metal basis unchanged; only a changed metal basis reprices them. This was corrected after an independent UI/API comparison and is covered in both helper and real-browser checks.

A Design selection can change visible Touch/West/Labour defaults without changing cached amounts. A later actual numeric blur, including an unchanged visible copied cell, executes the source cache pipeline and recalculates the bounded fine/metal/net preview. An untouched imported manual labour cell does not invent a new event merely because it was focused and left. A rate commit before a later ghat commit retains whole-rupee117 in the exercised example; this is event-order behavior rather than a final-state-only formula.

The current browser intentionally preserves a Design when the operator cancels the picker. Independent MS_HELP tracing found an ambiguity/difference: Load1058 starts HelpClose=false, row load1235 allocates empty ColValue, Escape2236 only closes, and Closed2388 does not set HelpClose; the empty-return path may clear Design/Image in the desktop caller. Web cancellation preservation is therefore a deliberate loss-prevention difference requiring desktop/business acceptance, not claimed identical cancellation parity. Explicit clear remains available and journaled.

- Prior-year confirmation and its lock exception require an explicit business policy and executable desktop evidence. They remain rejected with a clear diagnostic.
- Bank/card/UPI split tender, old-metal receipt, scheme/rate-cut/order allocation and conversion workflows remain separate unfinished slices. Saved settlement values are displayed read-only; this editor does not invent missing settlement movements.
- Tag reservation, replacement, issue/delivery/conversion transitions and transferred image files remain outside this lifecycle implementation. Saved source/tag identity is read-only; backend blocking remains in force.
- The full later desktop total/MRP/tax chain, special tag branches, numeric midpoint behavior and item-specific policy need independent source vectors and production acceptance. Reuse of the bounded existing fine/metal/net helper is not evidence that every later formula has been transferred.
- Picker cancellation behavior requires acceptance as described above. A source-preserving cancel is not silently counted as exact desktop equivalence.
- The misleading editable header Net Amt override was removed from ordinary Sales: Saved Net Amount is read-only and preserves its persisted value. Read-only header settlement/derived controls now have explicit read-only labels, shaded backgrounds and dashed borders. The browser asserts the saved amount control is read-only and matches the loaded amount; visual verification is recorded with final screenshots. - Production acceptance still requires representative customer data migration, representative real business workflows, financial/stock reconciliation, permission roles, report comparison and operator sign-off under the global plan gates.
