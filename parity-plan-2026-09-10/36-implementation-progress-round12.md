## Implemented behavior

The new exported core module `sessionLedgerMode` implements the qualified company-open and subsequent semantic-command branches. A successful company opening is required. Opening editions A/E select A unless the trusted combined-mode exception selects C; the other reachable editions select C. The edition observed during a later command is separate from the opening edition, so changing edition does not silently reset mode or erase history.

The resolver retains the source literal company01 catalog, even when the selected company differs. For special A/B/C commands, a missing sentinel permits direct selection; a present sentinel uses the matching alias, with the source A fallback when that alias is absent. General D–Z aliases select their exact supported output or retain the previous mode when absent. Unknown catalogs do not count as empty catalogs. Relevant duplicate or noncanonical keys, unsupported outputs and unresolved facts produce explicit diagnostics. True foreign-company and NULL-company rows remain in provenance but do not satisfy the source company predicate.

State includes context identity, version, profile, bootstrap observations and accepted command proofs. Inputs are detached, results recursively frozen, and history is replayed to verify semantic consistency. Malformed or unsupported transitions preserve a valid previous state. This is a pure trusted-data module: it does not authenticate those facts, establish a current session, prevent replacement with an independently fabricated compatible history, grant edition rights, decode registration, route raw keyboard events or persist a mode. Its bounds of 100 commands, 1,000 catalog rows and 8 MiB text are explicit transport-profile limits, not desktop limits.

The new internal API helper `observeDesktopAccountBalanceTx` implements the qualified `DC_Main.MsAcBal` query semantics for an already resolved mode, canonical scope/account and qualified local whole-second cutoff. It uses one SQL statement inside a tenant-bound RepeatableRead or Serializable transaction. It reads the complete matching company/location/year/account ledger across all books. Opening uses `ENTRY_TIME < cutoff`; the original helper closing uses `ENTRY_TIME <= cutoff`. It applies no voucher, book or `VCH_DATE` restriction. Mode C applies no data-type filter, including NULL and other stored types; A/B apply their respective type filter.

Amount uses `SUM(CR_AMT - DR_AMT)`, preserving NULL arithmetic before aggregation. Gold and silver use the source conditional signed fine-weight expressions. Non-plus ordinary ASCII signs follow the source negative branch; other item types contribute zero. An absent account group produces initialized F2/F3 zero values. A present group with a NULL aggregate remains unresolved and cannot be defaulted to zero. All three helper fields are checked before the observation is ready. The reader returns exact raw groups, raw rows, physical row identity/revision/location, diagnostics and separate opening/helper-closing phases.

The named PostgreSQL fixed-decimal profile formats exact numeric strings without JavaScript Number monetary arithmetic. Unsupported numeric values and comparison representations remain explicit. The dependency version includes the selected scope, mode, cutoff and all matching candidate raw/physical observations, including alias candidates that make the result unsupported. Same-value physical updates, included rows from another book and present-row recreation invalidate it. A complete absent→present→absent cycle can return the original hash; this is a snapshot dependency version, not durable session generation or financial-write authority. Future/NULL-time and foreign-scope rows remain outside this intentionally scoped observation.

One independently authored cross-book case has opening amount14 in A,20 in B and39 in C; including the entry at the exact cutoff changes the helper closing to42,20 and67. The corresponding C gold/silver values are0.875/2.000 opening and1.875/2.000 helper closing. These are synthetic fixed-decimal cases, not measured customer balances or independent Windows execution results.

The pure exported `projectSavedSaleReturnClock` qualifies the saved reader's PostgreSQL JSONB representation: date-only `VCH_DATE` and local `VCH_TIME` with a `T` separator and an optional fraction of one to six digits. Both calendar dates must be valid. It combines the voucher day with the timestamp's `HH:mm:ss`; `23:59:59.999999` stays `23:59:59`, without day rollover. It preserves raw cells, missing-versus-NULL distinctions and detached document provenance. Invalid envelopes and unsupported clocks cannot produce a cutoff. This profile neither authenticates those observations nor proves original Windows locale parsing. Its [implementation evidence](evidence/implementation-2026-09-11-round12/x13-saved-return-clock-implementation.md) supersedes only the still-prospective clock step in the earlier frozen round12 handoff.
