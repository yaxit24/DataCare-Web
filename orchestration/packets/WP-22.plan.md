## Goal

The study and the frozen case list for the menu Company → Year Create are done (`orchestration/work/WP-22/`).
Turn them into (1) a design document a reviewer can check in ten minutes, and (2) the work packets that cheaper
sessions will run to build the change. You write no application code and no tests.

## Why this package is risk tier A

The core change is the first-year copy: which baseline rows and columns a new company starts with (study gaps 1
to 4). That code runs for **every company the service ever provisions**, and a wrong row set is silent: a missing
account, book slot or tax row shows up weeks later as a posting that cannot resolve its account. The design must
therefore say, table by table, what changes for a newly provisioned company, and which test proves the new row
set still lets a company sell, buy and take a receipt.

## Facts you need

- **The packet format.** Use `orchestration/packets/WP-22.cases.md` in this worktree as the model for the header
  and the brief.
  - A packet is a Markdown file. It starts with a title line and one fenced `json` block, then the brief.
  - Header fields: `id` (equal to the file name without `.md`), `wp`, `title`, `role` (one of `tests`,
    `implement`, `ui`, `verify`, `records`, `review`, `fix`), `tier` (`C` for a bulk model, `B` for a stronger
    one), `risk` (`A` for this package), `branch` (`agent/wp22-year-create`), `dependsOn` (packet ids),
    `allow` (globs of the paths the session may create or change: as narrow as its output), `outputs` (files
    that must exist afterwards), `context` (files to read first, as `path` or `path:start-end`), `inline`
    (short `path:start-end` excerpts pasted into the prompt), `gates`, `limits` (`minutes`, `maxChangedFiles`,
    `maxDiffLines`).
  - Gates are objects: `{ "type": "cmd", "cwd": "web", "run": "pnpm typecheck", "timeoutMin": 15 }` or
    `{ "type": "cite", "file": "<path>", "requireSnippets": true }`.
  - The brief has `## Goal`, `## Facts you need`, `## Steps` or `## What to cover`, `## Out of scope` and
    `## Done when`. It is written for a model that has never seen the project: it names files and line ranges,
    the existing example to copy, the commands to run and the nearest wrong turn. "Done when" lines are checks.
  - Roles and what they may touch: `tests` writes tests only; `implement` writes API and domain code and cannot
    change tests; `ui` writes the page and its components and cannot change the API or tests; `review` reads
    and reports.
- **This machine cannot run database or browser tests** (no Docker). Local gates can only be
  `pnpm typecheck` (from `web/`), `node --check <file>` for `.mjs` files, and unit tests that need no database
  (`pnpm --filter @datacare/core exec vitest run test/<file>`). Database tests and the browser suite run on
  GitHub CI after a push. Say this in every packet whose work CI must prove, and make each such packet list the
  tests it wrote but could not run.
- **Size rule.** A source file may not pass 1,500 lines, and `web/apps/api/src/routes/txn.ts` may gain at most
  two lines. Give the current line count of every file a packet will touch (`wc -l`) in that packet's facts.
  `seedCompany.ts` is 865 lines, `companyClone.ts` 531, `year.ts` 172.
- **Decisions already made** are the nine numbered facts in `orchestration/packets/WP-22.cases.md`: follow the
  desktop's first-year row selection and column values; the alternate-year branch is in scope and the UAE rule is
  not; a duplicate year stays refused; desktop rights and date messages verbatim; year-code length and format
  written to the desktop rule with the difference listed for the owner; party import and editing an existing
  year are blocked for the owner; restore and purge, Print, Delete and carry-forward do not apply.
- **Existing tests that depend on today's row set.** `web/apps/api/test/provisioning.db.test.ts` and any test
  that provisions a company and then posts a voucher. Search for the provisioning helper's callers and for
  hard-coded counts (for example a count of `BOOK_DETL` rows) before you size the change: a count that changes
  must be updated by a `tests` packet in the same package, with the desktop citation that justifies the new
  number.
- **The Company package (WP-07) shares this code.** `seedCompany.ts` and `companyClone.ts` are also the base of
  company provisioning. Keep the change behind one function boundary so that package can reuse it, and say so in
  the design.

## What to produce

1. `orchestration/work/WP-22/design.md`, at most 250 lines:
   - a table, one row per copied table: today's rows and columns for a new company, the desktop's (cite the
     study's lines), and exactly what changes;
   - what must not change: the accounts, book slots and tax rows that the voucher writers resolve at posting
     time. Name the resolver functions and show that each still finds its row after the change;
   - the alternate-year branch: how the year code and dates are derived, and what the API accepts;
   - the page: texts, keys and focus that change; nothing more;
   - the order of the work so that `main` is never left with a row set that breaks provisioning: tests that pin
     today's behaviour that must survive, then the change with its new expectations, table by table if the
     tables are independent;
   - a table mapping every executable case in `cases.md` to the test layer and the packet that covers it;
   - the risks, and for each the test that catches it. Include: a posting account that no longer resolves; a
     second tenant's baseline rows read or changed; a half-finished copy left behind by a failure; two requests
     creating the same year at once.
2. The packets, in `orchestration/packets/`, each small enough for its model (one role, one output, about 400
   changed lines at most). At least: database tests of the copy (one or more packets, by table group); the copy
   change itself (tier `B`); the alternate-year branch with its tests; the page; an independent review. Use
   tier `B` for anything that changes what a new company is provisioned with.
3. State the order and what can run in parallel.

## Out of scope

- Application code, tests, the catalog and the backlog.
- Reopening the nine decisions. Balance transfer between years. The Company screen itself.

## Done when

- `orchestration/work/WP-22/design.md` exists, with the per-table change table and with every executable case of
  the case list in its mapping table.
- The packets exist, each with a valid header and the five brief sections.
- Your report lists every decision you made that the owner might make differently, and names any existing test
  whose expected numbers will change.
