## Goal

Write the database tests that prove the Cash Bank report's numbers through the real HTTP route, before the route exists
(test first). They must fail today with `404` and pass once `WP-17.api` is built. Expected values come from the desktop rule
worked out in `cases.md`, never from the web's output.

## Facts you need

- The route contract is in `orchestration/work/WP-17/design.md` sections 1 and 2: `GET /reports/cash-bank?fromDate=YYYY-MM-DD&toDate=YYYY-MM-DD&acCode=00001[&bookCode=...]`
  returns `{ rows, totals, account, book, from, to }`. A row has `kind` (`opening` or `detail`), `sr`, `book`, `vchNo`, `vchDate`, `party`, `area`, `drAmt`,
  `crAmt`, `balAmt`, `side` (`Cr`, `Dr` or empty). `totals` is `{ drAmt, crAmt, balAmt, side }` or `null` when there are no rows.
  Exports: `GET /reports/cash-bank/export.xlsx` (and `.csv`, `.pdf`) need the print right; without it the status is 403 and the message is `You Have No Print Rights.....`.
- The model to copy is `web/apps/api/test/accountLedgerReport.db.test.ts` (read lines 1 to 200): it builds the app on the isolated database with forced row-level security, signs in as a
  non-administrator with report rights, seeds `AC_DATA`, `AC_MAST`, `BOOK_DATA` directly (the report has no web writer) and asserts through `app.inject`. Copy its insert column lists; do not guess columns.
- Seed A and its variants are in `cases.md` lines 638 to 673 ("Test data"). Put the seeding into `web/apps/api/test/support/cashBankSeed.ts` as exported functions (`seedA`, `seedVariant(name)`, `seedSecondTenant`, `seedSentinels`, `wipe`) because
  `WP-17.tests-print` imports it. Needed beyond the ledger model: `BOOK_DATA` rows for CASH REC, CASH PAY, CONTRA, SALES (book code, book name, `MAIN_BOOK`), one `SL_DATA` row (book SALES, voucher 6, `AC_NAME` `PARTY ALPHA`).
  **Voucher 7's two lines must share one `LEDR_KEY`; every other line gets its own `LEDR_KEY`** (the ledger notes that a web `LEDR_KEY` is unique per line; the desktop groups by it).
- Users: one with the view and print rights, one with the view right and no print right, one with no right for the Cash Bank form. Find how the ledger test grants rights and copy it. Rights form name: `Reports/Cash / Bank Book`.
- Cases to cover, each as an `it` named with the case id: balance.opening-row, balance.opening-zero-no-row, balance.opening-cr-side, balance.running-side, balance.zero-net-row-blank, balance.totals-row,
  balance.totals-include-opening (add a second vector: two lines of 0.10 and 0.20 on one day must total 0.30, not 0.30000000000000004), balance.seed-a-hand-totals, balance.date-boundary-from-inclusive,
  filter.date-window-from, filter.date-window-to, filter.from-after-to, filter.empty-period, filter.one-account-only, filter.book-filter, filter.book-empty-all, filter.book-unknown-code,
  account.enter-found (the route part: `account` is `{acCode:'00010', acName:'TEST BANK'}` and the rows), row.voucher-book-and-number, row.party-name-counter-party, row.party-name-sales,
  row.grouping-one-row-per-voucher, history.live-party-name, scope.company-sentinel, scope.location-sentinel (also a second tenant: its lines never appear), rights.menu-no-right (403), rights.excel-no-print (403 and the text), print.excel-rows-and-totals
  (read the xlsx with the library the ledger test uses, if none, check status 200 and content type only and write `Not done: cell values` in your report), print.excel-bold-and-autofit (header row bold, column widths set; same method).
  Each assertion block quotes the desktop line from `cases.md` in a comment.
- Prefix the `describe` with `enabled ? describe : describe.skip` exactly as the ledger test does (`RUN_DB_INTEGRITY_TESTS === '1'`). That is the repository's own pattern; do not add other skips.

## Steps

1. Read the ledger test and `cases.md` lines 19 to 83 and 638 to 673.
2. Write `cashBankSeed.ts`, then the test file, in the order of the case list above.
3. Run `pnpm typecheck:tests` and `pnpm lint` from `web/`.

## Out of scope
