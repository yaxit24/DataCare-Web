## Goal

Decision D33 says a Lite tenant's navigation shows only the 49 Lite menus (the `MENU_DATA` rows with `SM_TYPE` `L`;
desktop `MDI_FORM.cs:11249-11322`). `editionNav.test.ts` proves Standard and Beta but nothing proves the Lite list
is **exactly** the 49. Write `web/apps/web/test/editionNavLite.test.ts` (copy the style of `editionNav.test.ts`):

1. Load `docs/handbook/menu-editions.json` (`menus[]`, each with `menu`, `edition`, `catalogId`, `visible`,
   `separator`); the expected set is the 49 rows with `edition === 'L'` (assert the count is 49 first).
2. `editionNav(NAV, { code: 'L', beta: false })`: map each shown item to its form with `navItemForm` (read
   `lib/editionNav.ts` for how an item names its form/catalog id) and assert the set of shown catalog ids equals the
   49 expected ids: list the missing ones and the extra ones in the failure message.
3. Every shown item's `href` is classified edition `L` in `docs/handbook/web-route-editions.json`.
4. The Lite menu captions on the navigation equal the desktop captions (`menu`) character for character, or the test
   lists each difference.

If the test is red, that is a finding: write in `orchestration/work/WP-55/red.md` exactly which menus are missing,
extra, or captioned differently, so a fix packet can be written. Do not change `nav.ts` or any source.

## Done when

- The test file exists with the four checks; `red.md` lists the result (green, or the exact differences).
- Typecheck, lint and prettier pass (the vitest run itself may be red; that is the finding).
