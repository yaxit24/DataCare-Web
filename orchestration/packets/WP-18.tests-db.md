## Goal

Write the database tests that pin the new HuId report resolver before it exists. They call the real route `GET /reports/huid` (and the three
export routes) on the isolated database and compare with values computed by hand from the desktop rules. They are red until packet `WP-18.api` is done.

## Facts you need

- The design: `orchestration/work/WP-18/design.md` sections 1 and 2 (query parameters, response shape `{view, from, to, columns, rows, totals}`, row keys
  `tagNo, huId, grwt, netWt, ...`, totals keys `qty, pcs, grwt, netWt, huWt, huWt2, huWt3, huWt4`, weights as decimal strings).
- The seed is "Test data" in `cases.md` lines 896-937 (16 origin tags TG-001..TG-016, three sentinels). Insert it with the owner client the way
  `reportScreens.routes.db.test.ts` does (look at its `beforeAll`, `exec`, `get`, `LOGIN`, `YEAR`). Scope is company `01`, location `01`, year from the file's `YEAR` constant:
  map the case list's "2026-27" to that year and the prior-year sentinel to the year before. Each tag is one `BAR_DETL` row plus the `MAIN_STOCK` movements the table lists
  (a `+` row at the origin, `-` and `+` rows for sales and returns). Items, product, group and account masters are needed for `ITEM_MAST` (IT_TYPE, PR_CODE, GR_CODE).
- Model for a database test file: `web/apps/api/test/reportScreens.routes.db.test.ts:1-190`. Copy its structure; do not invent helpers.
- The old test at lines 151-175 of that file (`G13`) asserts the old behaviour of `/reports/huid` (default All, `hallmark=with`). The route is replaced, so rewrite that one test to
  the new contract: `view=in` with the full year window, `hallmark=with` and `without` on `HM_ID`, `hallmark=maybe` gives 400, the CSV export contains the tag. Keep the `D3` test as it is.
  The old `p9Reports.db.test.ts` calls the old resolver directly and stays untouched.

## What to cover (one `it` each; ids in the title)

Derive every expected value from the case text in `cases.md` (it shows the sum for the stock rule); copy the case id into the test title.
1. Windows: `filter.in-date-window` (10 tags), `filter.out-date-window` (TG-005, TG-006), `filter.stock-to-date-only`, `filter.tag-n-excluded`.
2. Filters: `filter.hallmark-with-first-slot`, `filter.hallmark-without-first-slot`, `filter.hallmark-slot-two-to-four-counts-as-without`, `filter.tag-no-exact`, `filter.item-type-silver`,
   `filter.product-ring`, `filter.group-link`, `filter.counter-absent` and `filter.item-code-absent` (extra `counter=C2` / `itCode=...` parameters change nothing), `filter.search-first-column-set`,
   `filter.search-second-column-match`, `order.tag-no-ascending`.
3. Totals: `total.in-window-sums`, `total.out-window-sums`, `total.stock-rule-sum`, `total.stock-rule-srno-zero` (TG-012 has serial 0), `total.stock-rule-sold-and-returned`.
4. Validation: `invalid.from-after-to-empty` (200, zero rows), `invalid.empty-result-no-message`, `invalid.search-apostrophe-no-error` (search `O'N` returns 200 and zero rows), missing `view` gives 400, bad date gives 400.
5. Scope and rights: `scope.other-company-never-appears`, `scope.other-location-never-appears`, `scope.prior-year-tag-never-appears`, `scope.other-tenant-never-appears` (a second tenant seeded
   with its own login must never see HUT001 and vice versa), `rights.view-refused-without-view-right` (403), `rights.print-refused-without-print-right` (CSV, XLSX, PDF each 403 `{"error":"forbidden","action":"print"}`).
6. No write: `write.view-leaves-bar-detl-unchanged` (give TG-004 a NULL `HM_ID2`; count and checksum `BAR_DETL` rows for the company before and after the three views; nothing changes, and the NULL is still NULL),
   `write.print-leaves-no-staging-rows` (the `TAG_STOCK_PRINT` row count for the company is the same before and after a PDF export).
7. Also `history.group-renamed-live-master`: rename a group in `GROUP_MAST` between two runs; the second run uses the same rows (the filter uses the group code).

If a case needs a value the seed does not give, stop and report it; do not guess.
