## Goal

Build the dedicated Approval Report screen at `web/apps/web/app/(app)/reports/approval-report/` split like
the GST Report page (`page.tsx`, a `use…` hook, a grid component, `types.ts`). It calls the existing RP_ALL approval API
in `routes/rpAllReport.ts`; do not change the API. Fields, their order, captions, defaults, modes, selectors,
help lists, refusal texts, output buttons and print rights follow study.md Screen/Keyboard and the Decisions and
cases of cases.md. The Reports navigation item "Approval Report" already points at `/reports/approval-report`, today
served by the generic `[report]` page; the new directory takes that route. Classify it as edition L in
`web-route-editions.json` and `editionTable.ts` if not already (regenerate with `node scripts/generate-edition-table.mjs`).

Make the locked browser module `approvalReportRp.mjs` pass. Do not edit it; if a case contradicts the desktop, quote
both and report PARTIAL.

## Done when

- Both gates pass: the `approval-report` module run prints FEATURE_E2E_PASSED (blocked cases allowed, no failures).
- The report lists the files, and any API gap under "Questions for the supervisor".
