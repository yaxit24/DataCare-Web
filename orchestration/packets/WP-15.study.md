## Goal

Write the study document for the menu **Report → Tag Stock**. The desktop form is `RP_TAG` (10,813 lines). It lists
inward, outward, in-stock, MRP, approval-pending and all tags with totals. The web has a first version: the page
`web/apps/web/app/(app)/reports/tag-stock/page.tsx` and `GET /reports/tag-stock` (+ `.csv`); find the API handler by
searching `tag-stock` under `web/apps/api/src`. The next workers will write the case list and the tests from your
document, so it must state every tab, selector, filter, column, total and key, each with a quoted citation.

## Facts you need

- The catalog points at `RP_TAG.cs:3977-4325` for the main query; read beyond it wherever the code leads.
- Templates named by the catalog: `TagStkRpt.rpt`, `CntrTagStkRpt.rpt`, `CntrTagSumRpt.rpt`. Search
  `extraction_output/rpt_xml/` before saying one is missing.
- Menu dispatch `MDI_FORM.cs:8891-8900`. `RP_TAG` is also opened at `MDI_FORM.cs:7157` and `:9819`; say which of
  those the Lite menu uses.
- The form is large. If you cannot cover everything, cover tabs, filters, query and grid columns completely first,
  list the rest under "Open questions" with line ranges, and report `PARTIAL`.

## What to cover

1. The tabs or modes (inward, outward, in-stock, MRP, approval-pending, all): how the operator picks one and the query
   each builds, with the tables (`MAIN_STOCK`, `BAR_DETL`, `BAR_IDTL`, `APR_DETL`) and conditions.
2. Every filter control and the condition it adds.
3. The grid: columns in order with caption, source column and format; the sort; totals; sub-details (stones,
   components); the tag image (`TAG_IMAGE_DATA`).
4. Print and export: templates, parameters, rights check and its message.
5. Keyboard: Enter order, Esc, F-keys.
6. Which tag states count as in stock: cancelled tags, sold tags, returned sale tags, approval-pending tags. Cite the
   conditions; this is what the tests will assert.
7. Web today and Gaps.
