## Goal

Build the read-only Cash Bank resolver and its routes exactly as `design.md` sections 1 to 3 say, so `web/apps/api/test/cashBankReport.db.test.ts` (written first, by `WP-17.tests-db`) passes on CI. Money is involved: a wrong sign, a lost boundary day or a leaked row is a wrong ledger.

## Facts you need

- The desktop rule is in `study.md` lines 95 to 152 (Calculations and Lifecycle); `design.md` sections 1 and 2 turn it into the contract. Cite the desktop line in a comment above each rule you implement (`RP_CASH_BANK.cs:3160`, `:3162`, `:3222`, `:3296`, `:3297`, `:3301`, `:3322` to `:3325`, copied from the study with the quote).
- The model is the Account Ledger: `accountLedger.ts` (plugin shape, `fail()`, guard use), `accountLedgerReport.ts` (parser, `withTxBudget(prisma, tenantId, 'read', …)`), `accountLedgerShared.ts` (`SIGNED_MONEY`, `splitSigned`, `sideOf`: reuse them, do not copy) and `accountLedgerQueries.ts:265-320` (a grouped detail query with bound parameters).
- Files and sizes: `cashBankKernel.ts` (pure: paise arithmetic, opening row, running balance, side, totals; no database import), `cashBankReport.ts` (parser, the two queries, the account help list, error classes), `routes/cashBankReport.ts` (plugin `registerCashBankReportRoutes(app, { prisma, auth, guard, readScope, sendReportPdf })`). Each file stays under 600 lines.
- Routes in this packet: `GET /reports/cash-bank`, `GET /reports/cash-bank/accounts`, `GET /reports/cash-bank/export.xlsx`, `GET /reports/cash-bank/export.csv`. The exports start with `if (!guard(req, reply, 'print')) return;` and the refusal text is `You Have No Print Rights.....` (check what `guard` sends; if its body cannot carry this text, set it in the handler with `reply.code(403).send({ error: 'forbidden', message: 'You Have No Print Rights.....' })` before calling `guard`'s check, and say so in the report). `/print` and `/export.pdf` belong to `WP-17.print`; do not add them.
- Excel and CSV columns, in order, with these captions: `Sr`, `Book`, `VchNo`, `Date` (`dd/MM/yyyy` text), `Party Name`, `Area`, `Dr Amt`, `Cr Amt`, `Bal Amt`, `CrDr`. Rows: the opening row (Book `Op Balance`), the detail rows, and the totals row (label `Total :` in `Party Name`). Money columns are numbers with format `0.00`; the header row is bold and widths are set (copy `columnsFor`/`sheetFor` of `accountLedger.ts`, and read `xlsx.ts` for how bold and width are set).
- Wiring (all one-line or few-line changes): in `txn.ts` add one `import` line and one call line `registerCashBankReportRoutes(app, { prisma, auth, guard, readScope, sendReportPdf });` directly under `registerAccountLedgerRoutes(…)` (`txn.ts:4519`). In `app.ts:403` add `if (url.startsWith('/reports/cash-bank')) return;` with a comment after the account-ledger exemption (otherwise `acCode` and `bookCode` are refused). In `routePolicy.ts` add the new routes to `route('Reports/Cash / Bank Book', […])` (line 946) and the xlsx and csv routes to `PRINT_ROUTES` (next to line 1048). Do not rename the form.
- Column names and types of `AC_DATA`, `BOOK_DATA`, `AC_MAST`, `SL_DATA`, `PR_DATA`: read `web/packages/db/prisma/schema.prisma` for exact names and whether amounts are numeric or text. Do not guess a column. If `BOOK_DATA` has no `MAIN_BOOK`, write `MISSING: BOOK_DATA.MAIN_BOOK` and stop as PARTIAL.
- Known unknowns (do not invent): the `MEMB ENTRY` party name (use the counter-party name and put a comment `desktop reads AD_DATA/AD_MEMB, RP_CASH_BANK.cs:3280, not ported`), the help list for location `00` (return an empty list), the data-type filter (not applied).
- No test can run here (no Docker). Run `pnpm typecheck`, `pnpm lint` and `node scripts/check-size-budget.mjs` from `web/`; the database tests run on CI.

## Steps

1. Read the model files and the test file. 2. Write the kernel, then the resolver, then the plugin. 3. Wire `txn.ts`, `app.ts`, `routePolicy.ts`. 4. Walk through seed A by hand against your queries: opening 7500.00 Dr, five rows, totals 13500.00 / 2500.00 / 11000.00 Dr (`cases.md` `balance.running-side`). Write the walk in the report.
