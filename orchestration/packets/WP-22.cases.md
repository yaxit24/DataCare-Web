## Goal

Turn the study of the menu Company → Year Create (`orchestration/work/WP-22/study.md`, 20 numbered gaps) into the
frozen case list. The next sessions write tests from your list and are measured against it, so each case needs
concrete steps and a concrete expected value derived from the desktop rule.

## Facts you need: the supervisor's decisions on the study's questions

The owner's standing rule is "the desktop first": the operator sees and does what the desktop does, and the web
adds only what an internet-hosted service needs to be safe. A destructive desktop behaviour is not ported.

1. **First-year copy: follow the desktop's row selection and column values** (gaps 1 and 2: the account codes
   below 101, location `00`, the selected item and group codes, the narrow column lists). These cases are the
   core of this package. Each one names the table, the selection rule and the expected rows or counts for a new
   company, worked out from the baseline rows.
2. **Tables the desktop never copies** (gap 3) and the duplicate `BOOK_DETL` entry (gap 4): a case each, expecting
   the desktop's result.
3. **The alternate-year branch** (gaps 9 and 11, the `YEAR_MONTH` company type) is in scope: the master plan
   names it as remaining work. **The UAE calendar rule** (gap 10) is out of scope: the Lite edition here is the
   India build. Mark its case `N/A` with that reason.
4. **A duplicate year** (gap 6): the web keeps its refusal. The desktop overwrites the year row and purges data,
   which is destructive and is not ported. The case expects a refusal that writes nothing. For the message text:
   if the study quotes a desktop text for an existing year, expect that text verbatim; if the desktop has none,
   say so in the case and expect the web's current text.
5. **Rights messages** (gap 15): the desktop texts verbatim, "You Have No Rights....." and
   "You Have No Print Rights.....", where the desktop shows them.
6. **Year-code length and format** (gaps 7 and 8): the web's `yyyy-yyyy` rule is a web-only restriction. Write the
   cases to the desktop's rule (what the desktop accepts and stores), and list the difference under "Not
   covered" as a decision for the owner, because existing web data and other screens may rely on the format.
7. **"Import All Party" from another company** (gap 5) and **editing an existing year** (gap 16): write the case
   from the desktop behaviour and mark it `blocked: owner decision` (a hosted service copying parties between
   companies, and editing a year that already holds vouchers, both need the owner's word).
8. **Restore and purge** (gap 12), **Print** (gap 13), **Delete** (gap 14), **carry-forward** (gap 19): not
   applicable, each with the study's reason. Add one case that proves the web has no Delete action on this
   screen.
9. **Date validation messages** (gap 18) and **keyboard** (gap 17): the desktop texts and keys.

## What to cover

- Every gap the study marks as real work has at least one case that fails today because of it. Name the gap
  number in the case.
- The first-year provisioning that is already right also gets cases, so the row-selection change cannot break it
  unnoticed: one case per copied table.
- T11: a second tenant and a second company see and change nothing; a user without the right is refused.
- T12: two requests creating the same year at once give one year. T14: a failure part-way through the copy
  leaves nothing behind.
- T18: a new company gets its first year, a party and an opening balance are entered, a second year is created,
  and the first year's data is untouched.
- The module id is `year-create`. Case ids look like `year-create.copy.ac-mast-rows`.

## Out of scope

- Writing tests or code. Changing the study. Balance transfer between years.

## Done when

- `orchestration/work/WP-22/cases.md` exists with one entry per case in the layout the role gives, the coverage
  table for T01 to T18, the test data section and the "Not covered" section.
- Every gap number 1 to 20 appears in at least one case or in an `N/A` entry with its reason.
- The citation check passes: every expected value carries its desktop citation with the quote, copied from the
  study.
