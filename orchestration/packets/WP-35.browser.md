## Goal

Replace each blocked browser case listed in `orchestration/work/WP-35/cases.md` with the executable, `N/A` or
still-blocked case it specifies, keeping the id mapping cases.md gives (old → new). Copy patterns: rollback cases
from `salesOrder.mjs` (uses `rollbackMatrix` from `faults.mjs:64`); a second operator slot from `companyOpen.mjs`
(T01 opens four sessions through `ctx.session()`); the stale-second-save shape from the Sales Invoice
`sales-invoice.concurrency.stale-second-save` case (grep it in `salesInvoice.mjs`).

`faults.mjs` (156 lines): add one option to `rollbackMatrix`, `fixedVoucherNo` (default false). When true it skips
`nextVoucherNo` and the "number unchanged" check and uses `o.voucherNoOf`. The existing callers must behave exactly
as before (the option is off by default). This is needed because Party Opening saves under `'00000'` and Item
Opening under the metal letter (study gaps 6 and 8).

Fine Jv T13 stays `blocked` with the reason "WP-04 batch B (agent/wp04-idem-lite) must merge first" (decision
D-35-1). Expected values come from the desktop rules quoted in cases.md, never from the web.

## Done when

- No case in the five modules keeps a blocked reason that cases.md resolved; every changed case carries its
  cases.md id and a desktop citation in `source`.
- `red-browser.md` lists each case, its status and the run command
  (`FEATURE_E2E_MODULES=fine-jv,party-opening,item-opening,company-open,settings`).
- The gate passes.
