## Goal

Turn the study of Company → Books (`orchestration/work/WP-21/study.md`, 13 numbered gaps) into the frozen case list.
Books carry the posting-account slots every voucher posts through, so the most important cases create a book through
the screen and then post a voucher on it through that voucher's own screen, asserting the ledger rows hit the slot
accounts that were configured.

## Facts you need: the supervisor's decisions on the study's questions

The owner's standing rule is "the desktop first"; the web adds only what a hosted multi-user service needs to be safe.

1. **Slot authority.** The desktop's `MS_UPDATE.cs` template inserts (`BOOK_IDTL`/`BOOK_DETL` rows the study cites,
   the latest patch for each family and slot) define each family's slots, meaning, direction and default account.
   Where the web seed (`seedCompany.ts`) differs (gaps 7 to 11), the case expects the desktop template.
2. **Codes.** The operator types the code: at most 3 characters; the reserved codes 218, 888 and 999 and a duplicate
   name are refused with the desktop's exact texts. The desktop has no automatic generation; the web adds none.
3. **Delete.** Follow the desktop guards exactly (`AC_DATA` by company and book; `MAIN_STOCK` by location), and delete
   header and slots together in one transaction.
4. **Family change on a book that has vouchers.** The desktop has no guard. The web refuses it, because a changed
   family silently re-routes postings. Use a plain web message, state the deliberate difference, and list it under
   "Not covered" for the owner to confirm. Do not invent a desktop message.
5. **Blank slot accounts** are allowed on save, as on the desktop; the Data Type stored for a blank is `A`.
6. **Not ported:** the Ctrl+O edit-lock override and the A/E footer company-wide reset. A case expects each absent.
7. **Print.** Without the Print right the desktop message "You Have No Print Rights....." is shown. With it, the
   desktop does nothing; the web's CSV export stays behind the Print right as a web addition, listed under
   "Not covered".
8. **Branch cloning** (`MS_LOCT.cs:3612-3614`): adding a location copies the books of location `00`. One case, if
   locations are reachable in Lite; otherwise `N/A` with the citation.
9. **Downstream journeys (T18).** At least: Sales, Purchase, Cash/Bank and Contra each posting through a book created
   or edited on this screen, with the expected ledger accounts worked out from the configured slots.
