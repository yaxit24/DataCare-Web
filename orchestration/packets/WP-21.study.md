## Goal

Write the study document for the menu **Company → Books**. The desktop form is `MS_BOOK` (3,122 lines). It defines
voucher series: a 3-digit book code, the `MAIN_BOOK` family, the in/out direction, and the posting-account slots in
`BOOK_DETL`. Every voucher's postings resolve accounts through these slots, so a wrong slot silently posts to the wrong
ledger. The web has only a generic master CRUD at `/masters/books` (`masters/configs.ts`) and seeds about 41 books in
`ops/seedCompany.ts`. The next workers will write the case list and the tests from your document.

## Facts you need

- Desktop entry points: Load `MS_BOOK.cs:1900`, Clear `:2434`, Display `:2468`, Print `:2570`, Save `:2579`,
  Delete `:2687`. Menu dispatch `MDI_FORM.cs:7441-7450`.
- Lite edition only: check `MsSoftType` conditions and state which controls and families the Lite operator sees.

## What to cover

1. Every `MAIN_BOOK` family the form offers and, per family, which `BOOK_DETL` slots exist, what each slot means
   (cash, bank, income, expense, tax, labour, round-off, kasar, gold, silver, debit or credit), which are mandatory,
   and the account lookup filter for each slot. Put this in a table under "Calculations" or "Lifecycle and write set".
2. The book code rules: 3 digits, generation, uniqueness, the message texts.
3. Save: every table and column written, the key, the statement order. Delete and family change: the reference
   guards (vouchers on the book) with the exact message texts.
4. Branch cloning (`LC_CODE`) if present, and the family-filtered book list.
5. Print, rights, keyboard (Enter order, Esc, F-keys).
6. Web today: what `configs.ts` does for books, which seeded books and slots `seedCompany.ts` creates, and which
   web posting code reads `BOOK_DETL` slots (search `BOOK_DETL` under `web/apps/api/src/modules`).
7. Gaps: each desktop behaviour the web lacks or does differently, in particular seeded slots that differ from what
   the desktop form would allow.
