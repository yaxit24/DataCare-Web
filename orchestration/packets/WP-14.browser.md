## Goal

Write the browser feature module `orderReportRp.mjs` (feature id `order-report`, decision D12 of cases.md) for every
`browser` case in `orchestration/work/WP-14/cases.md`, before the screen exists. Copy the structure, helpers, seeding
and evidence shape of `salesReport.mjs` (the sibling RP_ALL report): `C(...)` cases with group T01-T18, kind, desktop
source citation and `run(ctx)` returning `{ observation, expected, ... }`. The screen will be the dedicated route
`/reports/order-report`, opened from the Reports navigation link "Order Report"; use the desktop captions, labels
and message texts quoted in cases.md character for character. Seed orders through the real API or the same SQL
helpers the sales-order module uses; expected totals are computed in the test from the seeded rows with the
desktop formula quoted in the case, never read back from the app.

Every T01-T18 group must be dispositioned: a case with no browser layer becomes `notApplicable(...)` or
`blocked(...)` with a reason citing where it is covered (for example `web/apps/api/test/rpAllOrder.db.test.ts`) or
what unblocks it, exactly as `salesReport.mjs` does. Register the module in `run-features.mjs` and add its
coverage-map entry (the API files of `modules/reports/rpAll/` order branch and the future page directory).

## Done when

- Every browser case id of cases.md appears as a case id `order-report.<group>.<name>`.
- `red-browser.md` lists the cases, the blocked/N/A ones with reasons, and the command to run them.
- Both gates pass.
