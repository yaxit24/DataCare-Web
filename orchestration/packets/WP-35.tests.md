## Goal

Write the `database` cases of `orchestration/work/WP-35/cases.md` for decision D-35-2 (Fine Jv concurrency) in a new
file `web/apps/api/test/fineJvVersion.db.test.ts`, copying the setup and seeding of `fineJv.routes.db.test.ts`.
Contract (D17, `docs/master-parity-plan-2026-09-29/11-audit-implementation-plan-2026-10-01.md` line 128, and how
`routes/approval.ts:162-205` already does it):

- `GET /fine-jv/:vchNo` answers a `version` field: 64 lowercase hex characters, the value
  `modules/vouchers/version.ts` computes for the voucher's write set.
- `PUT /fine-jv/:vchNo` and `DELETE /fine-jv/:vchNo` require `expectedVersion` (body for PUT, query for DELETE).
  Missing or malformed → 400. Stale (another save happened since the GET) → `409` with
  `error: 'voucher-version-conflict'`, and nothing is written (compare the `CONTRA_DATA`, `AC_DATA`, `ROJ_MEL_DATA`
  rows before and after).
- A save with the current version succeeds and the next GET returns a different version.
- Two clients: both GET, the first PUT succeeds, the second PUT with its old version gets 409, and the stored voucher
  equals the first save.

Record each test, the command (env `PARITY_TEST_PORT=55637`) and its failing lines in `orchestration/work/WP-35/red.md`;
list the browser cases of cases.md as "for WP-35.browser".

## Done when
