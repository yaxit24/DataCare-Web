## Goal

Write the study document for the menu **Company → Balance TrFr**. The desktop form is `BtmSchm` (5,638 lines). It
carries balances into the next financial year, one button per dataset. A wrong carry is silent and moves money, gold
fine, silver fine and stock, so this package is priority P0. The web page `company/balance-transfer/page.tsx` and the
API `POST /balance-transfer/preview|year-close|openings` (module `web/apps/api/src/modules/ops/yearEnd.ts`) carry only
account and party openings today. The next workers will write the case list and database tests that prove
closing(year N) = opening(year N+1) per account and per item, from your document.

## Facts you need

- Load `BtmSchm.cs:1929`. Buttons: `BtnAcBalence :2724` (accounts), `BtnItmStk :2921` (item stock),
  `BtnTagStock :2169` (tags), `BtnOrder :3003` (sales orders), `BtnApr :4116` (approvals), `BtnDhrn :3602`, and the
  loan, scheme, repair, lot and manufacturing buttons: find each handler.
- Menu dispatch near `MDI_FORM.cs:7433`.

## What to cover

1. Classify every button by edition first: which are visible or enabled when `MsSoftType` is the Lite value. Each
   one outside Lite is recorded with the citation that hides it. Put this table at the top of "Scope".
2. For each Lite dataset: the source query of the closing year (tables, conditions, grouping), the formula that
   turns it into an opening (sign, debit or credit side, gold fine, silver fine, amount, rounding), the target table
   and columns of the new year, and the statement order. Quote the formulas.
3. What happens on a second run: does the form delete and rewrite the openings, refuse, or double them? Cite it.
4. Transactions: is each dataset one transaction, or can an interruption leave half a carry? Cite the code.
5. Rules and messages verbatim, rights, print, keyboard.
6. Web today: what `yearEnd.ts` carries and how, line by line against the desktop formulas.
7. Gaps, numbered.
