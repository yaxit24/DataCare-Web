## Goal

Write the browser feature module `yearCreate` in the style of `companyMaster.mjs`, covering the browser-layer cases of the case list, and register it. The screen
does not support most of them yet (packet `WP-22.ui` builds it), so those cases fail until then: that is expected.

## Facts you need

- The browser suite cannot run on this machine (no Docker, no browser stack). Local gates: `node --check` on the two `.mjs` files. Say so in the report.
- Read `companyMaster.mjs:1-120` (563 lines) for the case builder `C(id, group, kind, source, run, extra)`, the `as(user, slot)` helper and how a case reads the
  database. Registration: `run-features.mjs` imports the module (line 27 pattern) and lists it (line 76 pattern); `coverage-map.json:54` shows the entry shape for `companyMaster`.
  Add the minimum lines to both files; change nothing else in them.
- Fixed element test ids on the page (the `ui` packet creates exactly these): `year-code`, `year-month`, `year-opening`, `year-closing`, `year-save`, `year-cancel`, `year-exit`,
  `year-message`, `year-list`. Use them as `[data-testid="..."]`.
- Clock: the suite must set the page clock (use the harness's clock helper if one exists in `harness.mjs`; if it has none write `MISSING: clock helper` and mark those cases
  `applicable: false` with that reason, do not guess). Dates: 16 Nov 2026 and 15 Feb 2027.
- Case texts are the specification; each expected value is already worked out there:
  `entry.*` `cases.md:23-76`; `validate.closing-before-opening-refused`, `duplicate-year-refused`, `date-day-invalid-desktop-text`, `month-invalid-desktop-text` `:156-192`;

- Do **not** write cases for the blocked ones (lookup, edit, import, party-master-shared, success message, 12/15-character year code) nor the N/A ones; list them in the module
