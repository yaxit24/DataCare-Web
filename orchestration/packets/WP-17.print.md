## Goal

Add `GET /reports/cash-bank/print` (html in the layout of the Crystal template `AcLedger`) and `GET /reports/cash-bank/export.pdf`, both refused without the print right, built from the same resolver result as the screen so print and screen cannot disagree.

## Facts you need

- Regions and captions are fixed in `design.md` section 5 and `cases.md` lines 395 to 437: title `Cash and Bank Report From dd/MM/yyyy To dd/MM/yyyy`; page-header headings `Debit Rs`, `Credit Rs`, `Ac Name`, `Balance` (`AcLedger.xml:452`, `:465`, `:478`, `:511`); group header `Opening Balance :` (`:581`); group footer `Transaction Total :` (`:836`) and `Closing Balance :` (`:917`). The template has more headings (book, voucher, date columns): read `AcLedger.xml` lines 440 to 520 and list **every** `<Text>` heading you use with its line number in a comment. Do not invent a heading; if one is unreadable, write `MISSING: <what>`.
- Values: the opening in the print is signed, Cr positive (seed A: `-7500.00`, `AcLedger.xml:285`). Transaction Total Dr is the opening's absolute value (when the opening is below zero, `:323`) plus the period Dr; Cr is the opening (when above zero, `:307`) plus the period Cr; Closing Balance is Cr total minus Dr total, side `Dr` when below zero (`:350`). For seed A these are 13500.00, 2500.00 and 11000.00 `Dr`. The kernel's totals already include the opening: use them, do not recompute.
- Zero-balance side and the printed balance column format are decided questions (`cases.md` print.balance-zero-side, print.balance-column-format are blocked): follow the grid (blank side at zero), write `two decimals, minus sign for Dr` as the format, and name both in the report under "Not done or not verified".
- The html builder is a pure function `cashBankPrintHtml(result, { company, coYear })`: escape every inserted string (party names are user data), no script, no external resources, A4 landscape style. Money is shown with two decimals and no thousands separator inside the template cells that the tests compare, or with them; the tests strip separators, so either works.
- Route handlers go in `routes/cashBankReport.ts` (the file `WP-17.api` wrote): `/print` returns `reply.header('content-type','text/html; charset=utf-8').send(html)`; `/export.pdf` renders through the existing renderer. Read `txn.ts:4490-4520` (`sendReportPdf`): if it builds its own generic html from `result` and cannot take your html, **stop as PARTIAL** and write what a one-function addition to `txn.ts` would have to be; do not edit `txn.ts` (not in your allow list). Both handlers start with the same print guard as the xlsx route.
- The old data to avoid: the desktop's print opening ignores the book filter (study weakness 2). Here the opening comes from the same resolver call as the rows.
- No test runs here. Run the three gates from `web/`.
