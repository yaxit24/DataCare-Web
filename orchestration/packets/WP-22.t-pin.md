## Goal

Write one new database test file that proves, on today's code, that a company created through Year Create gets a row set it can
sell, buy and take a receipt with, and that a failed create leaves nothing behind. These tests must **pass today and keep passing**
after the copy change (packet `WP-22.impl-copy`). They are the safety net for risk tier A.

## Facts you need

- Database tests cannot run on this machine (no Docker). They run on GitHub CI. You can only run `pnpm typecheck` and
  `pnpm typecheck:tests` from `web/`. Say so in your report and list every test you wrote but could not run.
- Copy the setup style (owner and runtime Prisma clients, `TENANT`, cleanup) from `web/apps/api/test/companySettings.db.test.ts:1-50`
  (259 lines) and the book resolver use from `web/apps/api/test/provisioning.db.test.ts:296-335` (628 lines).
- `seedCompany(prisma, tenantId, coCode, {lcCode})` in `web/apps/api/src/modules/ops/seedCompany.ts` (865 lines) builds a template
  company with named accounts (`CASH`, `SALES`, `ROUNDOFF`), books at location `01`, taxes and a year. Use it for the template `01`.
  `createYear(runtime, {tenantId, coCode}, {coYear})` is in `web/apps/api/src/modules/masters/year.ts` (172 lines). A company with no
  `YEAR_MAST` row gets the clone (`year.ts:87`, `:106`). Company `01` itself is never cloned into itself.
- `seedCompany('01')` also writes a `YEAR_MAST` row for `01`; that is fine, the new company `04` has none.
- The resolvers: `resolveBookAccountTx(tx, scope, policy, srNo)` and `resolveBookPolicyTx` in `shared/bookPolicy.ts` (186 lines);
  `resolveTaxPolicyTx` in `shared/taxPolicy.ts` (see how `provisioning.db.test.ts:304-335` and `:413-440` call them).
- You cover the cases `year-create.create.first-year-footprint`, `create.further-year-no-copy`, `create.footprint-no-vouchers` and
  `rollback.copy-failure-leaves-nothing` (read them in `cases.md:194-226` and `:582-600`; their expected values are the desktop result).
  Where a case's expected value is the **new** baseline row set (the copy cases), do not assert it here: other packets do.

## What to cover

1. **Footprint.** First year of company `04` from a `seedCompany('01', ..., {lcCode:'01'})` template: one `YEAR_MAST` row with the stated
   columns; `AC_GROUP` and the other copied tables have rows; the second year of `04` writes exactly one more `YEAR_MAST` row and no other
   table changes row count; no voucher or ledger table has any row for `04`.
2. **Posting resolvers still find their rows.** After the first year of `04`, inside `withTxBudget(runtime, TENANT, 'read', ...)`:
   `resolveBookPolicyTx` for book `SAL` at the company's location; `resolveBookAccountTx` slots 1, 2, 3 each return the same account code as for
   company `01`; every `BOOK_DETL.AC_CODE` of `04` exists in `04`'s `AC_MAST`; every `BOOK_DATA` book has at least one `BOOK_DETL` row;
   `resolveTaxPolicyTx` resolves one GST code by percentage for `04` to the same result as for `01`. The new company's location equals the
   template's (`01`). These are the key assertions: write each `expect` message so a failure says which account or book is missing.
3. **Rollback.** With the owner client create a trigger on `TAX_MAST` that raises an exception on insert for `CO_CODE='04'`
   (`CREATE FUNCTION` + `CREATE TRIGGER`; drop both in `finally` and in `afterAll`). `createYear` for `04` must reject; afterwards `YEAR_MAST`
   and every table in `COMPANY_CLONE_TABLES` have zero rows for `04`; company `01` row counts are unchanged.
4. **Tenant isolation of the copy.** Create tenant B with its own company `01` holding a row in `AC_GROUP`; after tenant A's `04` first year,
   tenant B's counts are unchanged and none of B's rows appear under A's `04`.
