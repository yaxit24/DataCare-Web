## Goal

Write the study document for the menu **Report → Cash Bank**. The desktop form is `RP_CASH_BANK` (4,813 lines).
It shows the cash book and the bank book, and it has further modes for scheme members and pending items; it
drills down from a balance into the account's movements and prints through Crystal templates. The web has only
`GET /reports/cash-book` behind a generic report page. The next sessions write the case list and the tests from
your document.

## Facts you need

- The menu opens the form at `MDI_FORM.cs:8941-8950` (excerpt in section 6). The catalog points at
  `RP_CASH_BANK.cs:2084-2357` for the main query; the form is much larger than that, so use the form index to
  find the load, the mode switches, the drill-down, the print and the keyboard handlers.
- **Editions.** The desktop shows a menu only in its edition and above; the excerpt of `MDI_FORM.cs:11236-11330`
  shows how. This work is for the Lite edition (`MsSoftType` is `L`). For every mode, tab or button of the form,
  state whether a Lite operator can reach it, with the line that decides it. A mode Lite cannot reach is listed
  under Scope as out of scope with that citation, and you do not study it further.
- Tables the catalog names: `AC_DATA`, `AC_MAST`, `BOOK_DATA`, `CASH_DATA`, `UPI_DATA`, `AD_DATA`, `AD_MEMB`
  (the last two belong to scheme members).
- Templates the prompt names: `RojMelCash.rpt`, `AcLedger.rpt` and the PassBook layouts. Their extracted XML is
  under `extraction_output/rpt_xml/`: search there before you call a template missing.
- The web today: `GET /reports/cash-book` is registered in `web/apps/api/src/routes/txn.ts` (around line 6540)
  and calls `cashBook(...)`. Find that function, the page that shows it, and any test or browser module.

## What to cover

1. Each mode the Lite operator can open: how it is chosen, the query it builds (tables, joins, every condition,
   grouping, order), and the opening-balance logic.
2. Every filter control and the condition it adds: dates, account, book, cash or bank, any search box.
3. The grid of each mode: columns in order with caption, source and format; running balance; totals.
4. Drill-down: what a double-click or Enter on a row opens, and how it finds the voucher.
5. Print: the rights check and its message, which template each mode prints, the parameters passed.
6. Keyboard: Enter order through the filters, Esc, function keys.
7. Rights checks (`USER_SET`) and their messages.
8. Web today, and the gaps: each desktop behaviour the web lacks or does differently.

## Out of scope

- Writing code, tests or the case list. Modes the Lite edition cannot reach (after you have cited why).
- Other reports.
