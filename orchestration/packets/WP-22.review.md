## Goal

Read the finished change as a reviewer who did not write it and say, with evidence, whether a company provisioned after this change can still sell, buy and take a receipt, and whether
tenant isolation, atomicity and the two-requests case hold. You write only `review.md`.

## Facts you need

- Do not run the database tests (no Docker here). Read code and tests; run `pnpm typecheck` and `pnpm lint` from `web/` only to quote their last lines.
- The design's risk list is `design.md` section 10. Check each risk against the code and name the test that covers it; if no test covers it, say so.
- Desktop citations in `review.md` use `FILE.cs:LINE {{copied text}}`.

## What to cover

1. **Every table of the design section 2 table**: does the code do what the table says (rows, columns, constants)? One line per table, with the code line.
2. **Resolvers:** for each resolver in design section 3, show from the code that its row still exists after the copy for both template shapes (desktop numeric / web-seeded). Look for any filter that could
   leave `BOOK_DETL` without its `AC_MAST` row, and for `CAST` of a non-numeric account code that could raise an error.
3. **SQL safety:** no request value in SQL text; `tenant_id` in every statement, including `assertBaselineUsableTx` and the `CO_MAST` flag read.
4. **Atomicity:** the year row, the copy, the integrity check and the lock are in one transaction; the lock key has the tenant in it.
5. **`selection: 'all'` is unchanged:** compare the branch to the old code.
6. **Alternate year:** code that parses `CO_YEAR` as `yyyy-yyyy` (`grep` for `split('-')`, `slice(0, 4)`, `/^\d{4}-\d{4}$/` on year codes in `web/apps/api/src` and `web/apps/web`) and would break on `202611`; list each hit.
7. **Page:** test ids present, desktop texts verbatim, Carry Forward untouched.
8. **Size rules:** line counts of every changed file; `txn.ts` gained at most two lines.

## Out of scope

- Fixing anything. Editing any file except `review.md`. Re-deciding the owner's decisions.

- A final list "Must fix before merge" and "Can wait", each entry with a file and line.
- The two command outputs are pasted.
