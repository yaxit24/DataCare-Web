## Goal

Turn the study of the menu Report → HuId Report (`orchestration/work/WP-18/study.md`, 29 numbered gaps) into the
frozen case list. The next sessions write tests from your list and are measured against it, so each case needs
concrete steps and a concrete expected value derived from the desktop rule.

## Facts you need: the supervisor's decisions on the study's questions

The owner's standing rule is "the desktop first": the operator sees and does what the desktop does, and the web
adds only what an internet-hosted service needs to be safe. Apply it as follows.

1. **Views.** The web follows the desktop: three views, Stock, In and Out. The web's "All history" tab has no
   desktop button; write a case that expects exactly the three desktop views, and list the removal of the fourth
   tab under "Not covered" as a decision for the owner to confirm.
2. **The stock rule.** Use the desktop rule exactly:
   `HAVING SUM(CASE WHEN ITM_SIGN='+' THEN A.VCH_SRNO ELSE -A.VCH_SRNO END) > 0`. It is not a defect: about
   forty-five desktop forms use the same expression to decide that a tag is in stock (for example `RP_TAG.cs`,
   `TR_SALE.cs`, `TR_TAG_CAN.cs`). Compute each expected Stock result with that expression from the seeded
   movements, and show the sum in the case.
3. **Print and export rights.** The web refuses Print and every export for a user without the Print right, as the
   report addendum requires. This is a deliberate difference from the desktop, whose Print button has no check;
   say so in the case.
4. **Item type default.** As the desktop: the box opens on Gold (Silver when the company's metal type says so),
   so the first run is filtered to that type.
5. **HUID present or absent.** As the desktop: the test reads the first HUID column only (`HM_ID`), and an empty
   string is the only "absent" value.
6. **Date window and financial year.** As the desktop: In and Out are bounded by From and To on the voucher date
   and by the open financial year; Stock is bounded by To on the stock date.
7. **Filters the web has and the desktop does not** (Counter, Item code): the desktop has no such filter. Write a
   case that expects them to be absent, and list them under "Not covered" for the owner to confirm.
8. Questions the study could not answer (the meaning of `CO_STK_MERGE`, the Crystal formula bodies, the
   drill-down targets, stored precision): a case that depends on one of them is `blocked` with that reason.

## What to cover

- Every one of the 29 gaps in the study has at least one case that fails today because of it. Name the gap number
  in the case.
- The existing behaviour that is already right also gets a case, so a later change cannot break it unnoticed.
- For a report, T07 to T10 (create, reopen, edit, delete) do not apply to the report itself: mark them `N/A`
  with that reason. T16 (output), T11 (scope and rights), T04 (lookups), T17 (keyboard) and T18 (a journey: tags
  made through Tag Opening and a hallmark Purchase, then one sold, one cancelled, one returned, and the three
  views agree) carry most of the cases.
- The module id is `huid-report`. Case ids look like `huid-report.filter.date-window`.

## Out of scope

- Writing tests or code. Changing the study.
