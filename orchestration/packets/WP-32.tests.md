## Goal

Write the `database` cases of `orchestration/work/WP-32/cases.md` in one new file
`web/apps/api/test/tagOpeningResiduals.db.test.ts`, copying setup and seeding from `tagOpeningRoundTrip.db.test.ts`.
Contracts the implement packets will meet (use exactly these):

1. Counter stock (D-32-1): with `CO_SET.CNTR_STK = 'Y'` a POST or PUT `/stock/tag-opening` with a blank counter code on
   any line answers 400 with the text `Please Insert Counter Code and Try Because It is Mandatory...` and writes
   nothing (BAR_DATA, MAIN_STOCK counts unchanged); with `'N'` the same body saves. Test both books (OPSTK and
   TAG GEN).
2. Version (D-32-3): GET `/stock/tag-opening/:vchNo` returns `version` (64 hex); PUT (body) and DELETE (query) need
   `expectedVersion`; stale → 409 `voucher-version-conflict`, nothing written; current → success, new version.
3. Rights (D-32-2): a user without the create right gets 403 whose message is `You Have No Rights.....`; without
   the print right, the print route answers 403 `You Have No Print Rights.....`.
4. Print route (D-32-6): `POST /stock/tag-opening/:vchNo/print` with `{ labelSkip, labelFile }` answers the label
   document for the voucher's tags; `labelSkip` 2.5 gives 2 blank labels (banker's rounding as `tagPrint.ts:221-237`).
5. Rollback (D-32-5): a fault on MAIN_STOCK leaves no BAR_DATA row and no stock row (copy the trigger pattern used in
   an existing `*.db.test.ts`; search `RAISE EXCEPTION` under `web/apps/api/test`).

Record tests, command (env `PARITY_TEST_PORT=55634`) and failing lines in `orchestration/work/WP-32/red.md`.
