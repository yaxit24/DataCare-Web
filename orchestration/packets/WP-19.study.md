## Goal

The Gst Report browser module (`web/apps/web/test/features/modules/gstReport.mjs`) has 70 cases; 57 pass and 13 are
declared with `blocked(...)`, each with a reason. Statutory GST figures must be exact, so this package is risk A.
For **each blocked case**, find in the desktop source what settles it, and write a study that lets the next worker
turn the case into an executable one, or proves it must stay blocked.

## Facts you need

- Read every `blocked(` call in `gstReport.mjs`: its id, group, source and reason.
- Known item from the master plan: the web `LBR_ISU_DETL` has no discount column while the desktop sums
  `IT_DISC_AMT` (`RP_GST.cs:2719`); adding it needs a migration and its writer. EXP, EXEMP, DOCS and TCS sections are
  part of this WP; the UAE variant is out of scope.
- Shared helpers (`SetDate`, date checks) live in `DC_Main.cs`; trace them there.
- Quote every citation as `File.cs:N {{text}}`, including ranges and shared-form references, from the start.

## What to write (use the study role's twelve sections; put the per-case analysis in "Gaps")

For each of the 13 cases, one numbered Gaps item: case id; the blocking reason as written; what the desktop source
shows (quoted); the resulting expected behaviour and figures; what the web must change (file and line, migration if
any); or, if the source cannot settle it, the exact remaining question. Also list any posting path that feeds a GST
section (TCS, exempt, export, documents) with its writer.

## Out of scope

- Writing code or tests. The 57 passing cases, except where a fix for a blocked case would change them: name them.

## Done when

- `orchestration/work/WP-19/study.md` exists with the twelve sections, and every one of the 13 blocked cases has its
  own Gaps item.
- The citation check passes with at least 25 citations, all quoted.
