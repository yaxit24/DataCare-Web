## Goal

Add the second half of the Cash Bank browser module: the cases for drill-down, rights, keyboard and reset, and the registration of every blocked and not-applicable case, so no case of the frozen list is missing from the run.

## Facts you need

- Import the helpers from `cashBankReportKit.mjs` (written by `WP-17.tests-ui`): `as`, `C`, `blocked`, `notApplicable`, `exec`, `button`, `seedA`, `seedVariant`, `cleanCase`, `openReport`, `readGrid`, `ROUTE`. Export `ioCases(kit)` returning the case array, and add one line to `cashBankReport.mjs` that spreads it into `cases` (that is the only change allowed in that file).
- Cases to write, each with the id prefix `cash-bank-report.` and the steps and expected values of its `cases.md` entry:
  - drilldown.sales, cash-rec, cash-pay, bank-rec, bank-pay, contra, sales-order (double-click the row; assert the URL and that the voucher screen shows the voucher number). The URL for each book is **not known**: read how `web/apps/web/app/(app)/txn/sales/page.tsx` (line 504 opens `/txn/sales/<vchNo>?coBook=&coYear=&lcCode=`), `contra`, `receipt`, `payment` and `sales-order` open a saved voucher. If a screen has no way to open a saved voucher by number, register that case with `blocked(...)` and the reason; do not invent a URL.
  - reset.cancel-clears-all; rights.menu-no-right (a user without the right: no grid, message `You Have No Rights.....`), rights.ctrl-f11-no-right, rights.excel-no-print (message `You Have No Print Rights.....`, no download).
  - keyboard.tab-order (From, To, Party Code, Print), enter-from-moves-on, enter-to-moves-on, enter-party-refills, enter-book-refills, esc-closes, enter-in-grid-no-action, upper-case-codes, focus-direct.
  - The Print button opens the print preview (a new tab or frame with `GET /reports/cash-bank/print`): one case `print.button-opens-preview`, source "design.md section 5", kind `read-only`, no desktop figure beyond the title text of print.title-parameter.
- Blocked cases (use `blocked(id, group, reason)`; take the reason from the `Status:` line of the entry): filter.date-change-no-refresh, filter.data-type-rule, account.help-location-00, account.name-readonly, drilldown.sales-hm-tax, drilldown.purchase, drilldown.unconfirmed-books, drilldown.opening-row-no-open, reset.delete-button-inert, scope.year-sentinel, rights.ctrl-f11-edition, rights.print-no-right-no-desktop-check, print.opening-with-book, print.balance-zero-side, print.balance-column-format, print.excel-column-set, print.generic-export-layout, journey.cash-and-bank-entries, journey.edit-and-cancel-follow.
- Not-applicable cases (use `notApplicable(name, group, source, reason)`): write.create (T07), write.reopen-no-op (T08), write.edit (T09), concurrency.two-sessions (T12), retry.unknown-ack (T13), rollback.partial-write (T14), lookup.stale-result (T04). Reasons from the entries.
- Run the rights cases with the second user (view right, no print right) that the kit seeds; if the kit has none, write `MISSING: user without print right` in the report and stop as PARTIAL.

1. Read the kit, the model module (lines 300 to 395 for rights and keyboard style) and the `cases.md` entries. 2. Write `cashBankReportIo.mjs`. 3. Add the spread line. 4. Run both `node --check` gates.
