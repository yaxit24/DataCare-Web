## Goal

Write the `database` and `unit` cases of `orchestration/work/WP-20/cases.md` before any implementation, copying the
seeding and the `app.inject` style of `accountLedgerReport.db.test.ts`. Route names to test (the implement packet
will create exactly these; literal paths):

- `GET /reports/account-ledger/jama-udhar` (JmUdAmt data), `GET /reports/account-ledger/gold-fine` (JmUdFine),
  `GET /reports/account-ledger/silver-fine` (JmUdFineSl), each with `/export.pdf` and `/export.xlsx` siblings, and
  the same query parameters as `GET /reports/account-ledger` (account, from, to, location).
- In Lite (the default edition, D33) the ageing view is refused: copy how `editionGate.test.ts` asserts 403
  `edition-unavailable`, for the request the page sends for "Debit Ageing" (read `accountLedger.ts` and the page
  hook to find it).
- A user without the Ledger Report print right gets 403 with the desktop text `You Have No Print Rights.....` on each
  export (quote `RP_LEDR.cs:8236`).
- Silver with no location selected answers 400 with `Please Select Lc Code and Try...`.
- Each data route writes nothing: count `FINE_DATA` and `LEDR_AC_DATA` rows before and after (both stay equal).
- Expected rows and totals are computed in the test from the seeded vouchers with the desktop formula quoted in the
  case, never read back from the app.

Pure shaping tests go in `ledgerFinePrints.test.ts`, route tests in `ledgerFinePrints.db.test.ts`. Record each test,
the command (env `PARITY_TEST_PORT=55623`) and the failing lines in `orchestration/work/WP-20/red.md`.
