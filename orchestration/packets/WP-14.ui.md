## Goal

Build the dedicated Order Report screen at `web/apps/web/app/(app)/reports/order-report/` (decision D12), split like
the GST Report page (`page.tsx`, a `use…` hook, a grid component, `types.ts`). It calls the existing RP_ALL order API
in `routes/rpAllReport.ts`; do not change the API. Fields, their order, captions, defaults (From `01/01/2010`, To
today: D11), the seven modes, disabled dead selectors (D8), hidden Employee/Select Book, Cust Name help (D9), the
date refusal text (D10), output buttons and print rights (D7) follow study.md Screen/Keyboard and cases.md. Point
the Reports navigation item "Order Report" at `/reports/order-report` (nav.ts) and classify the route as edition L
in `web-route-editions.json` and `editionTable.ts` (regenerate with `node scripts/generate-edition-table.mjs`).

Make the locked browser module `orderReportRp.mjs` pass. Do not edit it; if a case contradicts the desktop, quote
both and report PARTIAL.

## Done when

- Both gates pass: the `order-report` module run prints FEATURE_E2E_PASSED (blocked cases allowed, no failures).
- The report lists the files, and any API gap under "Questions for the supervisor".
