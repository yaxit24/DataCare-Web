## Goal

Write database tests for the new first-year copy of the accounts, locations, books and tables in group A. They describe the **desktop**
result (design section 2), so most fail until packet `WP-22.impl-copy` is built. They also prove the posting resolvers still find their rows
on a desktop-shaped template.

## Facts you need

- Database tests cannot run here (no Docker); CI runs them. Local gates: `pnpm typecheck`, `pnpm typecheck:tests` from `web/`. Report all as "written, not run".
- The new call the tests use is `cloneCompanyTx(tx, tenantId, coCode, { selection: 'baseline' })` and, through the route function,
  `createYear(runtime, {tenantId, coCode}, {coYear})`, which will use it. Test **both**: the clone directly with `{ selection: 'baseline' }`
  (`selection` is not in the `CloneCompanyOptions` type until `impl-copy` runs, so write the options as
  `const baseline = { selection: 'baseline' } as unknown as CloneCompanyOptions;` in ONE place at the top, with a comment that `impl-copy` makes the cast
  unnecessary), and `createYear` once per table group. The default (no `selection`) must still give the old result: assert that for AC_MAST once.
- Table specs and today's code: `companyClone.ts` (531 lines): `COMPANY_CLONE_TABLES` lines 23-456, `cloneCompanyTx` lines 475-520.
- Test data is in `cases.md:731-754` ("Test data"): template `01` AC_MAST rows `050` (LC `00`), `100` (LC `00`), `101` (LC `00`), `099` (LC `01`),
  `2001` (LC `00`), with the personal and GST columns filled and `DATA_TRFR = 'Y'`; BOOK_DATA 3 rows (LC `00`, `00`, `01`); BOOK_DETL 4 rows
  (LC `00`, `00`, `00`, `01`); LOCT_MAST 2 rows (`00`, `01`); TABLE_MAST codes `001`, `002`; also `AC_MAST_SRNO` and `BANK_RECONCILE` one row each.
- Expected results per case: read the case in `cases.md` (`copy.ac-mast-rows` :237, `ac-mast-columns` :245, `book-data-rows` :261,
  `book-data-columns` :268, `book-detl-rows` :276, `book-detl-listed-once` :283, `loct-mast-rows` :354, `table-mast-rows` :375,
  `ac-mast-srno-not-copied` :389, `bank-reconcile-not-copied` :397). Use the case's numbers; they come from the desktop rule, not from the web.
- Rule L and rule N are in design section 2: the baseline location is `00` when the template has a `00` location, otherwise the template's lowest
  location; account codes that are not all digits are kept.
- Use two templates: **desktop-shaped** (above) and **web-seeded** (`seedCompany(prisma, TENANT, '01', {lcCode:'01'})`, 865-line file
  `web/apps/api/src/modules/ops/seedCompany.ts`).

## What to cover

1. `year-create.copy.ac-mast-rows`: new company gets `050` and `100` only (not `101`, not `099`, not `2001`), and a mixed template with codes
   `CASH`, `050`, `101` creates **without a database error** and keeps `CASH` and `050`.
2. `copy.ac-mast-columns`: personal, address, GST and PAN columns are NULL; every new `AC_MAST` row has `DATA_TRFR = 'N'`.
3. `copy.book-data-rows`, `copy.book-data-columns`, `copy.book-detl-rows`, `copy.loct-mast-rows`, `copy.table-mast-rows` as written in the cases.
4. `copy.book-detl-listed-once` (unit, no database): `COMPANY_CLONE_TABLES.filter(t => t.table === 'BOOK_DETL').length === 1`.
5. `copy.ac-mast-srno-not-copied`, `copy.bank-reconcile-not-copied`: zero rows for the new company with `selection: 'baseline'`; one row each with the default.
6. **Posting still resolves (desktop shape):** after `createYear`, every `BOOK_DETL.AC_CODE` of the new company exists in its `AC_MAST`; account `101`
   is absent. **Web-seeded shape:** the new company has location `01`, `BOOK_DATA` count greater than 0, and `resolveBookAccountTx` slots 1-3 of `SAL` equal company `01`'s.
7. **Dangling reference refused, nothing written:** a template whose `BOOK_DETL` points at account `150` (not copied) makes `createYear` reject,
   and the new company has zero rows in `YEAR_MAST` and every table (this proves `assertBaselineUsableTx`, design section 3).
8. **Tenant B:** a second tenant's company `01` with the same codes is never read or changed.
