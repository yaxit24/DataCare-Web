## Goal

Review everything this work package added or changed since `main`, against the design, the case list and the engineering standards, as someone who did not write it. You change no code; you write `orchestration/work/WP-18/review.md`.

## Facts you need

- The diff: `git diff main...HEAD --stat`, then read each changed file under `web/`. (You may run read-only git commands; no commit, push or checkout.)
- What to check, risk first (`design.md` section 6): a row of another tenant, company, location or year reaching a list; the stock rule written as a count instead of the serial sum or placed in WHERE; Stock bounded by `from`;
  an In or Out window off by one; tag `N`; "With HUID" reading slots 2 to 4; weights summed as floats; any request value joined into SQL, a header or a file name; any write (`INSERT`, `UPDATE`, `DELETE`) in the resolver or routes;
  an export that runs before the Print guard; scope read from the query instead of the session.
- Also check: `txn.ts` net line count did not grow; no new file passes 1,500 lines; the generic report page is untouched; no test was skipped, focused or loosened; `baseline.json` has no new entry;
  every `huid-report.` id of `cases.md` that is executable has a test; the two old tests (`G13` rewritten, `D3` unchanged) still check what they claimed.
- Use `docs/handbook/web/engineering-standards.md` for style rules. Cite each finding as `path:line`.

## What to cover

`review.md` has: a verdict line (`PASS`, `PASS WITH FINDINGS` or `FAIL`); findings sorted by severity (blocker, major, minor), each with file and line, what is wrong, the case id that should catch it (or `none: add one`), and the smallest fix;
a list of the "What to check" items you verified clean, one line each; the list of tests CI must run (you cannot run them: no Docker).

## Out of scope

Fixing anything (a `fix` packet follows from your findings), reviewing other reports, style preferences the standards do not state.

## Done when

- `review.md` exists with the verdict line first.
- Every item of "What to check" appears as a finding or as "verified clean" with the file and line you read.
- `pnpm typecheck` result is pasted.
