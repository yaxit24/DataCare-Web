## Goal

Write the study document for the menu **Company → Year Create**. The desktop form is `MS_YEAR` (1,596 lines). It
creates a financial year for a company. An earlier review found that the existing prompt and catalog row
overstate what is left to build; your study must settle, with citations, exactly what remains. The next sessions
write the case list and the tests from your document.

## Facts you need (from an earlier review; verify each one in the source and cite it)

- Landmarks in `MS_YEAR.cs`: Load about line 759, Display 899, Print 961, Delete 970, Cancel 993, Save 1140, and
  `NewCompParmCreat` 1504-1595 (the copy of 17 baseline tables).
- **First year of a new company.** The 17-table copy runs only then (about lines 1357-1362). The web already does
  this in `web/apps/api/src/modules/masters/year.ts`. Compare the two table by table and list any difference.
- **A further year of an existing company.** The desktop restores the previous year's whole database as a new one
  and then deletes the other years' rows with many DELETE statements (about lines 1239-1282 and 1403-1502). The
  web keeps one database with a `CO_YEAR` column on every row, so there is no restore and no purge to port.
  Confirm this from the source, and state what the operator-visible result of the desktop action is (which data
  the new year starts with), because the web must give the operator the same starting point.
- **The alternate-year branch** on `YEAR_MONTH` (about lines 1153-1198) is believed not to be on the web.
- **Texts and checks believed missing on the web:** the message "Year Is Already Exist", the rights messages, and
  the print-rights check.
- **Do not port the Delete button.** It is visible on the form but runs the user-form routine: it asks "Are You
  Sure To Delete This User now?" and deletes rows of `LOGIN_MAST` and `USER_SET` (about lines 970-991). Document
  it under "Desktop weaknesses not to port" with the lines.
- A web-only year close and reopen was removed earlier (slice N90). Do not propose bringing it back.
- The web today: page `/masters/year-create`; API `GET /years`, `POST /years` and `POST /years/carry-forward`,
  registered in `web/apps/api/src/routes/txn.ts` (around lines 6352-6378).

## What to cover

1. The screen: every control with caption, tab order, default and enabled rule; what Display shows.
2. Save, step by step, for each branch: first year of a company; a further year; the alternate-year branch. For
   each: the validations and their exact message texts, the tables written with their columns, and the order.
3. The year code and date rules: how the year code, the from and to dates and `YEAR_MONTH` are derived and
   checked.
4. Print: what it prints, with which rights check.
5. Rights checks (`USER_SET`) and their messages; the Lite edition conditions, if any.
6. Web today, function by function, and the gaps: each desktop behaviour the web lacks or does differently.
   Mark each gap as real work, already done on the web, or not applicable to a single-database web (with the
   reason).
