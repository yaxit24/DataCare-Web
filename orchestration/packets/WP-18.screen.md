## Goal

Write `reports/huid/page.tsx`: the desktop `RP_HUID` screen on the web, using the hook and the grid of `WP-18.screen-data`. A static directory wins over the generic `[report]` route, so the old HUID block of the generic page stops being reached.
Do not touch the generic page (`[report]/page.tsx` is at its size ceiling).

## Facts you need

- The layout, order, captions and keys are in `design.md` section 3 and `study.md:35-100` (the study's Screen and Keyboard sections). The browser tests that will drive your page are in `huidReportFilters.mjs` and `huidReportOutput.mjs`:
  read them first; accessible names, labels and `data-*` attributes must match, and a mismatch is a defect of the page, not of the test (unless the test contradicts `design.md`, then report it).
- Model: `reports/account-ledger/page.tsx` (page shell, header, message area, `useX()` use, back navigation).
- Controls in tab order: From, To, Search, Item Type (Gold, Silver, default Gold), Product, Group, Tag No, the grid, buttons `Stock Tag`, `In Tag`, `Out Tag` (Alt+S, Alt+I, Alt+O), then HuId Type (All, With HuId, Without HuId) and Ac Code.
  Bottom row: `Print` (Alt+P), `Excel` (Alt+E), `Cancel` (Alt+C), `Exit` (Alt+X). No Delete button. No Counter or Item filter, no "All history" tab. Title `Tag Stock With HuId`.
- Product and Group lists come from the master lists other screens use: search `web/apps/web` for the Product and Group lookups (for example in the Tag Opening or Item Master pages) and reuse that lookup helper; do not add an API route.
- Keys: Enter in From moves to To; Enter in To moves to the next field; date boxes select their text on focus and are masked `dd/mm/yyyy`; Tag No and Ac Code upper-case what is typed; Enter in Tag No checks the tag and opens the existing tag help list when absent
  (the lookup the other screens use); Enter in Ac Code does the same for accounts and selects the text when the account exists; Esc leaves the page (the app's back navigation); ArrowUp and ArrowDown move focus to the grid; From has focus on open.
- Print, Excel and PDF come from `exportUrl`. If `printMessage` is set, show it in the page's message area and change nothing else. Excel and Print both follow the current search.
- Empty result: the grid is empty and no message is shown.

## Steps

1. Write the page, using the hook for all state and the grid for rows.
2. Check each accessible name and `data-*` the test files use against your markup, one by one; list the checks in your report.
3. `pnpm typecheck`, `pnpm lint` and `pnpm format:check` from `web/`. You cannot run the browser suite here (no Docker); CI runs it. Name the case ids you expect to pass and any you expect to fail.

## Out of scope

The hook, grid and types (change them only through a finding), the API, tests, the generic report page, drill-down (blocked), a Delete button, header-text decisions beyond the desktop aliases the API sends.

## Done when

- `page.tsx` exists and stays under 300 lines; `pnpm typecheck`, `pnpm lint` and `pnpm format:check` pass (paste the last lines).
- A search for `All history`, `counter`, `Counter` and `itCode` in the `reports/huid/` directory finds nothing.
- Your report lists, for each browser case id of T01, T17 and T11 (screen part), the markup that satisfies it.
