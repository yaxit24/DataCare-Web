## Goal

Decision D18 / slice N52 (gap G29, `LITE-MASTER-PLAN.md` WP-04): every voucher create route must carry the
`Idempotency-Key` guard so a replayed HTTP request never posts a second voucher. Seven routes are guarded today
(`GUARDED` in `web/apps/api/test/idempotencyRoutePolicy.test.ts`); the rest wait in `NOT_YET_GUARDED`. This packet
writes the **red tests** for three Lite routes, before the implementation: `POST /sales-orders` (Transaction →
Sales Order), `POST /tour/issue` and `POST /tour/return` (Approval Isu, Approval Rtn). Reuse the ids N52/G29: take no
new N or G id.

## Facts you need

- The mechanism is generic: `registerIdempotency` in `web/apps/api/src/modules/shared/idempotency.ts` wraps every
  route listed in `IDEMPOTENT_CREATE_ROUTES` (lines 44-80). The implement packet will add the three routes there.
- Pages send the key with `postCommand(path, body, command.key)` from `web/apps/web/lib/api.ts:179` and
  `const command = useIdempotencyKey()` from `web/apps/web/lib/idempotencyKey.ts`, then `command.renew()` after a
  successful save. Look at `web/apps/web/components/PaymentForm.tsx` for a page that already does it.
- The pages: `web/apps/web/app/(app)/txn/sales-order/page.tsx` line 426 posts
  ``post(`/sales-orders?${scopeQuery}`, payload)``; `web/apps/web/components/ApprovalVoucherForm.tsx` line 195 posts
  `post<SaveResult>(returning ? '/tour/return' : '/tour/issue', payload())`.
- Status codes: read each route's success status in its route file (`routes/txn.ts` or the sales-order route file
  for `/sales-orders`; `routes/approval.ts:313` and `:343` for the tour routes) and use that number.

## What to write

1. In `idempotencyRoutePolicy.test.ts`: move `'POST /sales-orders'`, `'POST /tour/issue'` and `'POST /tour/return'`
   from `NOT_YET_GUARDED` to `GUARDED`. Sender patterns (the implement packet must make the pages match them):
   - `'POST /sales-orders'`: page `app/(app)/txn/sales-order/page.tsx`, sends
     ``/postCommand<[^>]*>\(\s*`\/sales-orders\?\$\{scopeQuery\}`,\s*payload,\s*command\.key\s*\)/``
   - `'POST /tour/issue'` and `'POST /tour/return'`: page `components/ApprovalVoucherForm.tsx`, sends
     `/postCommand<[^>]*>\(\s*returning \? '\/tour\/return' : '\/tour\/issue',\s*payload\(\),\s*command\.key\s*\)/`
   Change nothing else in that file.
2. New `idempotency.liteBatchA.db.test.ts`, copied from the structure, setup, seeding helpers and `enabled` switch
   of `idempotency.routes.db.test.ts`. Seed a sales order and an approval issue/return body the way
   `salesOrderLifecycle.routes.db.test.ts` and `approvalLifecycle.routes.db.test.ts` do. For each of the three
   routes, three cases:
   - a replayed create with the same key answers the first status and body byte for byte, with header
     `Idempotency-Replayed: true`, and the voucher header table has exactly one new row (count before/after);
   - the same key with a different body answers `409` with `error: 'idempotency-key-reused'` and writes nothing;
   - two identical requests racing (`Promise.all`) with one key post one voucher.
   Name each test with the route, for example `Sales Order: a replayed create ... posts one voucher`.
3. `orchestration/work/WP-04/red-a.md`: each new test, the command, and the failing lines (or "not run" with the
   reason).
