## Goal

Write the first half of the browser feature module for the Cash Bank report (module id `cash-bank-report`): the shared helpers, seed A, and the cases that read the grid, the filters, the columns and the account lookup. They fail until `WP-17.screen` lands (the page is `/reports/cash-bank`).

## Facts you need

- Model: `web/apps/web/test/features/modules/accountLedger.mjs` (448 lines): the helpers `as`, `C`, `notApplicable`, the seed functions, cleanup by exact codes, and the `export const … = { feature, cases }` shape. The `blocked(id, group, reason)` helper is at `approvalIssue.mjs:47`.
- Put the shared helpers in `cashBankReportKit.mjs` and export them: `as`, `C`, `blocked`, `notApplicable`, `ROUTE = '/reports/cash-bank'`, `exec`, `button`, `seedA(ctx)`, `seedVariant(ctx, name)`, `cleanCase(ctx)`, `openReport(page, {from, to, acCode, bookCode})`, `readGrid(page)` (rows as arrays of cell texts). `WP-17.tests-ui-io` imports them.
- Seed A (`cases.md` lines 638 to 673): `AC_MAST`, `AC_DATA`, `BOOK_DATA`, `SL_DATA` through `ctx.owner.$executeRawUnsafe`, with codes owned by the module so cleanup is exact. Voucher 7's two lines share one `LEDR_KEY`; every other line has its own. Copy column lists from the ledger module (and from `web/apps/api/test/support/cashBankSeed.ts` if it exists).

Write each selector once in the kit, so one place changes if the screen differs.
