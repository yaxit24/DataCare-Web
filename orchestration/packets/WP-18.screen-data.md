## Goal

Write the three files the page of packet `WP-18.screen` uses: the response types, a hook that holds the filters and runs the view, and the grid that shows the rows and totals. They must match the API's
response exactly (`design.md` sections 1 and 3).

## Facts you need

- Model all three on the files of `reports/account-ledger/` (types, `useAccountLedger.ts`, `AccountLedgerGrid.tsx`): how the hook calls the API (the shared fetch helper), how it holds `loading`, `error` and the result, and how the grid renders.
- Types come from the API's response: read `huidTagReport.ts` and copy the row keys, the column list `{key, header, hidden, total}` and the totals keys. Do not import from `apps/api`; write the types again in `types.ts`.
- Hook `useHuidReport()` returns: filter state (`from`, `to` default to today's date from the system date as `dd/mm/yyyy` for the boxes and are sent as ISO; `itemType` default `G`; `product`, `group`, `tagNo`, `acCode` empty; `hallmark` `all`; `search` empty),
  setters, `run(view: 'stock' | 'in' | 'out')`, `clear()` (resets filters, dates, search and the result; the desktop Cancel), `exportUrl(kind: 'csv' | 'xlsx' | 'pdf')` and the last `view`. The request uses the query names in `design.md` section 2 only.
  A search change re-requests the last view after 250 ms (the grid filters on the server, so the exports agree). Before the first run the result is `null` and the grid is empty, with no message.
  A 403 `{error:'forbidden', action:'print'}` from an export is turned into the message `You Have No Print Rights.....` (`RP_HUID.cs:1361`), exposed as `printMessage`, and the grid is left unchanged. Exports are downloaded with the same authenticated fetch, not a bare link.
- Grid `HuidGrid`: props `{result, onRowDoubleClick?: never}`. It renders `role="grid"`, one `role="row"` per row, cells with `data-col="<key>"`, skips columns with `hidden: true`, shows the header text from the column list,
  and a last row `data-testid="huid-totals"` with the eight totals under their columns. The grid accepts focus (`tabIndex={0}`) so the arrow-key rule can move focus to it, and it exposes a `ref` for that. No drill-down handler (blocked).
- Format numbers as the API gives them (decimal strings); do not parse to floats for display or for totals.

## Steps

1. `types.ts`, 2. `useHuidReport.ts`, 3. `HuidGrid.tsx`. Each file under 250 lines. Use no `any`.
4. `pnpm typecheck` and `pnpm lint` from `web/`. The browser tests cannot run here (no Docker); the unit tests of the page are packet `screen`'s concern.

## Out of scope

The page file, the filter controls, keyboard handling, the API, tests, the generic report page.

## Done when

- Three files exist; `pnpm typecheck` and `pnpm lint` pass (paste the last lines).
- Every row key and totals key of `huidTagReport.ts` appears in `types.ts`.
- The grid has `data-col` cells, `data-testid="huid-totals"` and no `onDoubleClick`.
