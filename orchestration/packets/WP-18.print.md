## Goal

Add `GET /reports/huid/export.csv`, `export.xlsx` and `export.pdf` to the plugin written by `WP-18.api`. All three call the same resolver with the same query as the screen, refuse a user without the Print right before running
any query, and the PDF uses the `TagHuIdRpt` layout described in `design.md` section 4.

## Facts you need

- Model: `routes/accountLedger.ts` (its `columnsFor`, CSV, Excel and PDF handlers, lines 47-247). Copy the structure: `toCsv` from `modules/reports/reportCsv.js`, `renderXlsx` from `modules/reports/xlsx.js`, and `sendReportPdf(req, reply, slug, form, result)` for the PDF.
- Print right: `guard(req, reply, 'print')` must be the first line of each export handler; it answers 403 `{"error":"forbidden","action":"print"}` (`txn.ts:921-929`). The page shows the desktop text; the API keeps this body.
- Output content (decision 3 and `design.md` section 4): the visible columns only (`coCode`, `book`, `bookName` are hidden), search applied, weights as numbers in Excel, codes and dates as text. The PDF title is
  `Tag Wise Huid Report As on Date ` followed by the To date as dd/MM/yyyy (`RP_HUID.cs:2192 {{string text = "Tag Wise Huid Report As on Date ";}}`), rows grouped by product then group, group and report footers with the sums of the weights.
  The print selection also requires the voucher date `<= To` (`RP_HUID.cs:2219 {{{TAG_STOCK_PRINT.VCH_DATE} <= #}}`): for the PDF only, drop rows whose `vchDate` is after `to`. Every row carries `vchDate`, `prCode` and `grCode` as hidden fields (design section 1), which the print selection and the grouping use. If one is missing from the resolver output,
  stop as PARTIAL and say so: `huidTagReport.ts` is outside your allowed paths.
- Spec: `web/apps/api/report-specs/TagHuIdRpt.spec.json` already exists as a layout spec (study: no route reads it). Read it and use or extend it as `sendReportPdf` expects; follow how another spec is wired (search `report-specs` in `routes/txn.ts`).
- Policy: `routePolicy.ts:984` lists `GET /reports/huid`. Add `GET /reports/huid/export.csv`, `GET /reports/huid/export.xlsx`, `GET /reports/huid/export.pdf` to that same `route('Reports/HuId Report', [...])` call.
- No staging table, no write: the desktop's shared `TAG_STOCK_PRINT` is not ported; the PDF is built from the resolver result in memory.
- The file name of an export carries the report name and the To date, not a fixed name (`output.xlsx` is a desktop weakness).

## Steps

1. Add the three handlers and the column and PDF definitions to `routes/huidReport.ts`. Keep the file under 600 lines.
2. Update `routePolicy.ts` and, if needed, the spec.
3. `pnpm typecheck` and `pnpm lint` from `web/`. Database tests cannot run here (no Docker); name the tests in `huidReport.db.test.ts` that CI will run against these routes.
