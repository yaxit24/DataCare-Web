## Goal

Assemble the browser module for the HuId report: add the T18 journey, record every blocked and N/A case with its reason, combine the case arrays from the two earlier packets
into one exported module `huidReport`, and register it.

## Facts you need

- Module shape: the `accountLedger` export at the end of `web/apps/web/test/features/modules/accountLedger.mjs` (from line 155). Copy its fields (`feature`, `route`, `cases`, ...). Feature id `huid-report`, route `/reports/huid`.
- Registration: `web/apps/web/test/features/run-features.mjs` has one import line per module (line 48 for `accountLedger`) and the `MODULES` array (the line `accountLedger,`). Add an import and one entry. Do nothing else in that file.
- Coverage map: `web/apps/web/test/features/coverage-map.json` has an entry per module (see `"accountLedger"`). Add `"huidReport"` with `covers` listing the files of `design.md` section 3 (`web/apps/web/app/(app)/reports/huid/page.tsx`,
  `useHuidReport.ts`, `HuidGrid.tsx`, `types.ts`) and `web/apps/api/src/modules/reports/huidTagReport.ts`, `web/apps/api/src/routes/huidReport.ts`.
- Journey: `cases.md:844-893`. Create the journey tags through the screens with the existing modules' helpers (`tagOpening.mjs` for JT-1 and JT-2, `purchaseInvoice.mjs` for JT-3 and JT-4, `salesInvoice.mjs` for the sale,
  `salesReturn.mjs` for the return). Read each tag's `VCH_SRNO` from `BAR_DETL` after creation and compute the expected Stock sums from it. Import the helpers those modules export; if one is not exported, drive the screen in the case
  by copying the minimum steps and say so in a comment. Stage 4 (cancel) is blocked.
- Blocked and N/A cases are entries with `applicable: false` and `reason` set to the case's `Status:` text (copy `notApplicable` from the model). The lists are in `cases.md` (statuses `blocked` and `N/A`); the 15 blocked and 6 N/A case ids
  are exactly those whose `Status:` line says so.

## What to cover

1. `journeyCases`: `huid-report.journey.stage-1-tags-and-purchase-in-view`, `huid-report.journey.stage-2-sale-out-and-stock`, `huid-report.journey.stage-3-return-views-agree` in one sequence (a shared setup in the first case, torn down after the third).
2. One `applicable: false` entry for each blocked and N/A case id of `cases.md`, with its reason.
3. `export const huidReport = { feature: 'huid-report', ..., cases: [...filterCases, ...outputCases, ...journeyCases, ...blockedCases] }` and the registration in `run-features.mjs` and `coverage-map.json`.
4. Check by script that every `### huid-report.` heading of `cases.md` appears as an `id` once in the combined list (a `node -e` one-liner is enough; paste its output).

## Out of scope

The page, the API, editing the two earlier files (report a defect in them instead), the baseline file, any change to other modules.
