## Goal

Make the locked `ledgerFinePrints*.ts` tests pass. Put the read-only resolvers in a new
`modules/reports/ledgerFinePrints.ts` (one function per print, each inside `withTxBudget(prisma, tenantId, 'read',
...)`, reusing `acDataScope` and helpers from `accountLedgerShared.ts`), the PDF layout in
`ledgerFinePrintsPdf.ts` (copy how the existing `/reports/account-ledger/export.pdf` builds its PDF), and the routes
in a new `routes/ledgerFinePrints.ts` registered with one line beside `registerAccountLedgerRoutes` in `app.ts`.
Every route gets a policy in `routePolicy.ts` under the Ledger Report caption (view for the data, print for the
exports). Do not use `ledgerStaging.ts`: no write to `FINE_DATA` or `LEDR_AC_DATA` (decision D-20-2). Each rule
carries a `RP_LEDR.cs:<line>` comment copied from the study. Rounding only with `round`/`roundHalfEven` from
`@datacare/core`.

Lite ageing (D-20-1): refuse the ageing request in Lite with 403 `edition-unavailable`, through the existing edition
mechanism (`editionGate.ts` and `docs/handbook/web-route-editions.json`), not with an `if` in the handler. If the
ageing view is a query parameter of an existing route rather than its own path, add the smallest check that the
edition gate supports and explain it in the report.

Sizes: `accountLedger.ts` 247 lines, `accountLedgerQueries.ts` 591 (do not grow it; new code goes in the new files).
No file past 1,500 lines. Do not edit tests.
