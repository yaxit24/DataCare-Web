## Goal

Build the Cash Bank report screen as `design.md` section 4 describes, so the browser module (`cashBankReport.mjs`, `cashBankReportIo.mjs`) passes on CI. The screen shows the server's numbers and does no arithmetic of its own.

## Facts you need

- Model: the Account Ledger page, hook, grid and types in `reports/account-ledger/` (same split, same `get` and `downloadPdf` helpers from `lib/api`, same stale-response guard in the hook). Copy the style; the controls differ.
- API (from `WP-17.api`): `GET /reports/cash-bank?fromDate&toDate&acCode[&bookCode]` returns `{ rows, totals, account, book, from, to }` (row fields in `design.md` section 1); `GET /reports/cash-bank/accounts?q=` is the help list; `export.xlsx` and `export.csv` download; `GET /reports/cash-bank/print` is the print html (opened in a new tab with `openDocument`, as the ledger does; `export.pdf` is its PDF). A 403 body carries `message`: show it in the message line (`You Have No Print Rights.....`).
- The selectors the tests use are written once in `cashBankReportKit.mjs`: inputs named `From`, `To`, `Party Code`, `Book`; the name box `Account Name`; buttons `Print`, `Excel`, `Cancel`, `Exit`; grid `table.grid`. Read the kit and the second module and match them; if a test needs something this brief does not say, follow the test and say so in the report.
- Controls in DOM and tab order: From, To, Party Code, Print, Excel, Cancel, Exit, Account Name (read-only), the grid (focusable), Book with a read-only book-name box. No Delete button. The banner text is `Cash Bank`. Dates are `dd/MM/yyyy` on screen and `YYYY-MM-DD` on the wire; default both to the session date, Party Code to `00001`. Fill the name from the response (`account.acCode/acName`), never from a literal.
- Grid columns, in order: `Sr`, `Book`, `VchNo`, `Date`, `Party Name`, `Area`, `Dr Amt`, `Cr Amt`, `Bal Amt`, `CrDr`. Money with two decimals; a zero Dr, Cr or Bal shows blank; Bal shows the absolute value and `CrDr` shows the side. The opening row has `Op Balance` in Book. After the rows, the totals row has `Total :` in Party Name and the totals in Dr, Cr, Bal and the side. Hold the link keys (`coBook`, `mainBook`, `coYear`, `lcCode`) on the row object, never in a cell.
- Keys (design section 4): Enter in From focuses To; Enter in To focuses Party Code (call `.focus()`, never simulate keys); Enter in Party Code looks the account up and refills, and an account that does not resolve opens the help dialog (a modal list from `/accounts?q=`; arrow keys, Enter or double-click picks; Esc closes the dialog only); Enter in Book refills (empty book: all books, name cleared); Esc anywhere else leaves the report (`router.back()`); typed letters in Party Code and Book are upper-cased, no other box; Enter in the grid does nothing; a double-click on a detail row drills down. Refill on load, Cancel, Enter in Party Code, Enter in Book; **not** on a date change (the desktop does not; blocked case `filter.date-change-no-refresh`). Cancel resets Book, dates, account and refills, focus to From.
- Drill-down: only the books for which `cashBankReportIo.mjs` records a real URL. For a book without a URL do nothing and show no message. Do not invent a URL or a query parameter; if the test file has none for a book you need, write `MISSING: <book> voucher URL` in the report.
- Menu and keys: `lib/nav.ts:269` becomes `{ label: 'Cash Bank', href: '/reports/cash-bank', ready: true }`; `FormKeys.tsx:230-233` Ctrl+F11 gets label `Cash Bank` and `navigate('/reports/cash-bank')`. Do not touch `reports/[report]/page.tsx`.
- Each file under 400 lines. Use the existing CSS classes of the ledger page; no new global styles.
- No browser can run here. After the gates, say which of the module's cases you expect to pass and which depend on something you could not check.

## Steps

1. Read the ledger page set and the two browser modules. 2. Write `types.ts`, `useCashBank.ts`, `CashBankGrid.tsx`, `page.tsx`. 3. Edit `nav.ts` and `FormKeys.tsx`. 4. Run `pnpm typecheck`, `pnpm lint`, `pnpm format:check` from `web/`.

## Out of scope

The API, tests, the print layout, the generic report page, the old `cash-book` slug, drill-down URLs that the tests do not name, the Scheme Ledger mode.

## Done when

- The four files exist; the three gates pass (paste the last lines).
- `nav.ts` and `FormKeys.tsx` changed only on the lines named above; nothing else in the repository changed.
- Every case id of `cashBankReport.mjs` and `cashBankReportIo.mjs` has a line in the report: "expected to pass", "depends on X" or "blocked in the module".
- No cell shows a value the server did not send (no sums, no sides computed in the page).
