
# Lite feature-level parity matrix

Companion to `FEATURE-MATRIX.md` (49 menu rows, generated). This file goes one level down: one row per behaviour that differs, is missing, or is still unproven, with the desktop side and the web side cited separately. Written by hand on 2 November 2026 against `origin/main` `9c651837`. Summary and limits: `GAP-ANALYSIS-2026-11-02.md`. Ordered work: `PRIORITISED-BACKLOG.md`.

**No row says "complete".** Where a browser case passes, the row says what the case covers and that the Windows comparison is still missing.

**Evidence tags.** SRC: desktop and web code both read, lines cited. REPRO: reproduced in Docker (`evidence/`). CI: result of a browser case in CI run 41437234529 (main `bb1f6586`). GIT: read from git or `gh`. CAT: taken from the catalog or backlog and not re-checked by me.

**Priority.** P0 data integrity, security or business correctness. P1 missing core function or broken workflow. P2 behaviour or UI mismatch. P3 minor, or not provable without a desktop runtime.

**Owner.** "none" means no open PR, pushed branch or board claim at the time of writing. Register ids (G, N) are the project's own; `PA-nn` ids are new and have no register entry yet.

Desktop paths are under `unified/src/csharp/DataCareNext/`. Web paths are repo-relative. A bare `txn.ts:NNNN` means `web/apps/api/src/routes/txn.ts`.
