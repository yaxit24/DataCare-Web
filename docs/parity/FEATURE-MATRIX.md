**Desktop reference limit.** The desktop is available as decompiled C# source (`unified/src/csharp/DataCareNext/`), 1,069 tutorial-video keyframes (2021 build) and 254 extracted report XML specs. The Windows executable, the `.rpt` templates and the SQL Server backup are Git LFS objects (pointers in a fresh clone; all cached on the machine that produced this file), but the executable is a Windows .NET assembly and there is no Windows runtime to run it. ## Rules used

- **Status** is assigned in this order: BROKEN (an executed case fails), BLOCKED (half or more of the applicable cases are blocked, or the catalog row is CONTAINED), NOT YET VERIFIED (no module), MISSING (no web screen), else PARTIAL.
- A failing case outranks blocked ones, so Company shows BROKEN although most of its cases are blocked. Sales Order and Order Report share the `sales-order` module, so one failing case (`sales-order.create.scheme-tender`, G206) makes both rows BROKEN: that is one defect, not two.
- **Priority** is written by a person per menu in `PRIORITY` (P0 data integrity, security or business correctness; P1 missing core functionality or broken workflow; P2 behavioural or UI/UX mismatch; P3 minor, or not provable without a desktop runtime).
- **Owner** comes from `docs/parity/ownership.json`, which records open pull requests, branches and claims at the date in `AGENT-PROGRESS.md`. A menu with no entry is `unowned`.
- **Test Evidence** counts cases of the named feature module in the dated run. A blocked case is not a pass. See `TEST-EVIDENCE.md`.
