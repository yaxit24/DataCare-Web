# Supported devices and how to connect them

The devices the web version works with today, how each is triggered in the code, and how to connect it to a laptop.
This reflects the web code at the current baseline; real-hardware acceptance is slice N25, and until then every device
is driven in tests by a fake with recorded sample inputs (decision D29, slice N89). The desktop source is the
authority for what the ERP does with each reading; [Odoo's IoT documentation](https://www.odoo.com/documentation) is a
useful reference for the device **protocols** themselves.

## At a glance

| Device | Web entry point | Connection | Browser need | Desktop source |
|---|---|---|---|---|
| Weighing scale | `web/apps/web/components/ScaleCapture.tsx` → `web/apps/api/src/modules/integrations/scaleProtocol.ts`, `deviceBridge.ts` | USB serial (often a CH340 USB-serial adapter) | Chromium WebSerial | `TR_TAG_OPBL.cs:7499-7590` |
| Barcode / QR scanner | the active grid's tag field (keyboard-wedge) | USB HID (acts as a keyboard) | any | tag entry on sale/purchase/tag forms |
| Label / tag printer | `web/apps/api/src/modules/integrations/barcode.ts` (Code39, QR) → the tag-print document | USB or network printer, via the OS print dialog | any | `UT_TAG_PRINT.cs`, `PRINT_MAST` |
| Camera (item/tag photo) | `web/apps/web/components/CameraCapture.tsx` | built-in or USB webcam | Chromium `getUserMedia` | `UT_WEB_CAM.cs`, `Ac_Image.cs` |
| Document printer (invoices, reports) | the report engine renders a PDF; the browser prints it | any printer, via the OS print dialog | any | `MS_PRINT.cs`, Crystal templates |

`web/apps/web/components/DeviceCapabilityProbe.tsx` detects, in the browser, which of these the current machine
supports and shows it to the operator.

## Weighing scale

- **How it is triggered.** The operator opens a tag or weight screen and starts capture; the browser reads the serial
  port over WebSerial and the server normalises the frame (`normalizeScaleReading` in `deviceBridge.ts`, formatted to
  three decimals as the desktop does, `TR_TAG_OPBL.cs:7557-7590`). Capture is refused when the company setting
  `CO_SET.WEIGHT_PORT` is `0`, matching the desktop.
- **Protocol.** The desktop opens the port at **9600 baud, 8 data bits, no parity, 1 stop bit**; if that fails it
  retries the configured port at **2400 baud, 7 data bits, no parity, 1 stop bit** (`scaleProtocol.ts:20-21`). A
  reading is only taken while the cursor is in the net-weight cell.
- **Connect to a laptop.**
  1. Plug the scale's USB (or a USB-to-serial / CH340 cable) into the laptop.
  2. On Windows a CH340 driver may be needed; macOS and Linux usually detect it. Confirm a serial port appears
     (`/dev/tty.*` on macOS/Linux, a `COM` port on Windows).
  3. Use Chrome or Edge. On the screen, start capture and pick the port when the browser asks (WebSerial shows a port
     chooser the first time). Set the scale to continuous output at 9600 8-N-1.
  4. If no reading appears, try the 2400 7-N-1 fallback and check the cable is data-capable, not charge-only.

## Barcode / QR scanner

- **How it is triggered.** Most retail scanners are keyboard-wedge: scanning types the code into the focused field
  and presses Enter, exactly as on the desktop. No driver and no special API — focus the tag field and scan.
- **Connect to a laptop.** Plug in the USB scanner; it registers as a keyboard. Scan into any text field to confirm.
  Set the scanner to append Enter (a one-time configuration barcode in its manual) so the grid advances.
- **QR** on documents (UPI pay QR, e-invoice IRN QR, tag QR) is generated by the server (`barcode.ts`), not scanned.

## Label / tag printer

- **How it is triggered.** Tag Print selects tags and the server renders the label (Code39 and QR via `barcode.ts`)
  into a print document; the browser prints it through the OS. The desktop chose the layout from `PRINT_MAST`;
  template, size and font parity is tracked under N25/N73.
- **Connect to a laptop.** Install the printer in the OS (USB or network) so it appears in the print dialog. For
  dedicated label printers (for example thermal/Zebra), install the vendor driver and set the label size in the OS
  print preferences. Print a test label from the screen and check alignment.

## Camera (item and tag photos)

- **How it is triggered.** Image panels on item, tag, design and repair screens open the camera
  (`CameraCapture.tsx`, `getUserMedia`); the photo is stored as an entity image, as the desktop stores it in
  `NextImage`/`Ac_Image.cs`.
- **Connect to a laptop.** Any built-in or USB webcam works. Use Chrome or Edge and allow camera access when the
  browser prompts. A file upload is the fallback where no camera is available.

## Document printing (invoices, reports)

- Reports and invoices are rendered to PDF by the server and printed through the browser's print dialog, so any OS
  printer works. Copy labels (Original / Duplicate / Triplicate) follow the desktop.

## Integrations that are not local devices

These are online services, configured per deployment, not plugged into the laptop. They are off unless configured,
and an unconfigured one **fails honestly** — it never fakes a success (gap G33).

| Service | Code | Environment variables (names only) |
|---|---|---|
| E-invoice (GST IRN) | `web/apps/api/src/modules/einvoice/einvoice.ts` | `GSP_ASPID`, `GSP_PASSWORD`, `GSP_GSTIN`, `GSP_USER`, `GSP_EINV_PWD`, `GSP_SANDBOX` |
| WhatsApp | `web/apps/api/src/modules/integrations/messaging.ts` | `WA_PHONE_ID`, `WA_TOKEN`, `WA_API_VERSION` |
| SMS | same module | `SMS_URL_TEMPLATE`, `SMS_KEY`, `SMS_SENDER` |
| Live gold/silver rate | `web/apps/api/src/modules/integrations/rates.ts` | (deployment-specific) |

Set these only in your own environment, never in a committed file, and never send code, data or secrets to a service
that does not need them.

## Testing without hardware

You do not need a scale, scanner, printer or camera to build and test a slice. The device flows are driven in tests
by fakes with recorded sample inputs: `FakeMessageSender`, `FakeIrnTransport`, and the scale/camera fakes added by
slice N89. Build and prove a slice against the fakes and the desktop source; real-hardware runs are gathered once, at
acceptance (N25). See [testing](../web/testing.md).
