# Per-form business-logic & workflow catalog (Task 4)

Generated by `unified/tools/build_form_specs.py` from the decompiled C#, filtered to real catalog
tables (`data-model.json`). One `<FORM>.md` per form; classification + table-impact in
`../module-map.json`.

## Coverage
- **204 forms cataloged** — transaction 61, report 45, master 33, utility 22, other/helper 43.
- 57 transaction forms have detected write-posting.
- Each spec lists: tables written (INSERT/UPDATE), tables deleted/reversed (DELETE), tables read,
  the ordered save/operation sequence, and heuristic validation messages.

## Curated (flagship) specs — `curated/`
Hand-curated golden-master narratives interpreting the extracted evidence into the Req-4 structure
(save sequence → header/detail/ledger/stock/tax; validations; delete/reverse). These feed the web
build directly:
- `curated/TR_SALE.md` → Task 19 (Sales)
- `curated/TR_PURC.md` → Task 20 (Purchase)

Add curated specs for the remaining transaction forms (receipts/payments, Dhrn, Mfg, etc.) as their
web tasks (21–26) begin — a good sub-agent fan-out, one agent per form-group.

## Key architectural finding
Ledger posting is **centralized**: forms delegate `INSERT INTO AC_DATA (...)` to `Ac_Ledr.cs`
(double-entry, amount + metal fine). Editing a voucher = **delete-then-repost**. The web build
replaces this with an explicit transactional reverse+repost in the posting engine (Task 17).
