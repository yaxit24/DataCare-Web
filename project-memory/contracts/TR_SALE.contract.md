## Approval record — 2026-07-29

Every row above has a disposition, and no blanks remain.

**Validations** — 12 of 16 catalogued business rules carry the desktop wording in the web source. The
four remaining are dispositioned, not outstanding: three are WAIVED with dated evidence in `WAIVERS.md`
(two licence-serial gates and an edition-tier gate) and one is UI-LEVEL, firing when an action that needs
a persisted voucher is pressed — the API cannot be reached without a voucher number.

**Computed fields** — all 36 catalogued cells carry a golden-vector id:
- per-line money: `GV-SLDETL-001` (line total, whole rupees, half-to-even), `GV-GST-001/002`
- weights and fine: `GV-LINEWT-001`, `GV-FINE-001`
- exchange lines: `GV-OLDGOLD-001..005`, including the back-calculated-rate direction
- stone sub-detail: `GV-STONE-001` (priced per piece, not per gram)
- footer cells: `GV-TOTALS-001/002` — one vector covers all of them because the accumulation is
  identical per column; only the summed column differs
- non-monetary derived: `GV-SEQ-001` (row link serial)

**Defects found and fixed during this review**, none of which had prior test coverage:
1. `SL_DETL.TOT_AMT`/`NET_AMT` carried a tax-inclusive 2 dp figure and disagreed with each other; the
   desktop stores the same tax-exclusive whole-rupee value in both.
2. `gstSplit` rounded one head and gave the remainder to the other; the desktop stores two equal
   unrounded halves in `double precision` columns.
3. The exchange line trusted a client-supplied `CON_WT`/`NET_AMT` while deriving `ITM_FINE`
   server-side. Now derived from the desktop's branch set, with the typed-amount flow back-calculating
   the rate as the desktop does.

**Known limitation carried forward:** a `cUrConWt` branch gated on `SSRegSrNo = "KJ001NEKJ"` is not
implemented (fifth licence-serial gated rule, recorded in `WAIVERS.md`).
