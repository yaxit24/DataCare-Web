## Product contract

`packages/core/src/salesOrderDesign.ts` defines the source reference, display DTO, design-only event union, and pure application/clear helpers. It clones the caller's row and preserves all unassigned fields, identities, component objects and imported snapshots. Frontend decimal strings remain exact strings. Numeric server targets require an exact decimal→Number→decimal roundtrip; otherwise selection fails explicitly instead of rounding away supported NUMERIC(18,2) precision. Large-decimal arithmetic for those unsupported numeric targets remains open.

`packages/core/src/orderLabourWithCache.ts` implements only the source's amount→percentage→rate comparison block. It accepts separate visible values and prior cache84/85/86, returns their distinct next values, and is called only on an actual calculation trigger. The existing Tour Order helper is unchanged.

`apps/api/src/modules/sales/orderDesignSelection.ts` exposes:

- `listSalesOrderDesigns(prisma, fullSalesScope, {itCode,search?,offset?,limit?})`: real configured Sales family/table/direction, full scope, company-wide source designs for the server-resolved item product, display columns, stable pagination and literal search.
- `resolveSalesOrderDesignTx(tx, companyScope, {itCode,source})`: validates full saved source identity and SHA256 source version inside the order writer transaction. The version binds tenant/company/current item and all source display/copy fields, preserving raw decimal strings/nulls. It rejects changed/deleted/wrong-product/wrong-company/forged references before application. SHARE locks on current item and selected design block non-key concurrent edits until the selecting writer transaction ends.
- `getSalesOrderDesignImage(prisma, fullSalesScope, {itCode,source})`: validates configured Sales scope and the same saved source in one repeatable-read snapshot, then reuses the validated image decoder/resolver for company-level DESIGN/D/instance0. Blank/N source image cells return absent, never tag/custom fallback. Clients cannot supply an arbitrary image key.

The API lifecycle agent owns GET `/sales-orders/designs`, GET `/sales-orders/design-image`, Sales view rights, and ordered writer replay. `orderEdits` interleaves server-resolved design/clear events with actual field/labour commits; source defaults must never be re-applied after later manual changes. The writer determines A/E from the locked original parent. Existing fields/child identities are preserved; selection cannot trust a client-supplied prior financial snapshot.

A selected nonempty Design with a NULL/blank source image assigns an explicit empty image cell. That assignment is different from an omitted request field, unchanged imported NULL, or the explicit-clear marker N. The UI preserves source-assigned blank text in its request, and the writer persists authoritative replay text rather than losing the assignment through generic empty-text normalization. The source preview normalizes the nullable source ID to the copied empty cell; pending changes to the selected Design/image hide old saved-photo actions until save/reload. The browser checks below exercise the complete path, not only the pure copy helper or preview endpoint.

The read-only picker and preview live in `apps/web/components/SalesOrderDesignPicker.tsx`. The picker is mounted outside the order form, uses a native modal plus explicit Tab/Shift+Tab cycling for keyboard focus containment, handles Escape as web cancellation, restores the invoking Design input, shows every visible desktop help column, and separates request results by complete scope/item/row/query. Scope changes immediately hide stale results; delayed replies cannot repopulate another row's picker. A read-only image preview works in the dialog and after selection on an unsaved order row. The Sales page agent owns F1 entry, row/cache application, journaling, save/edit and the source preview context.

## Deliberate web protections and unresolved data anomalies

- Immutable identity/version checks and transaction locks are web concurrency protections, not claimed desktop observations.
- Duplicate product master records with identical labels collapse to the same valid display. Conflicting labels, contradictory registration modes, incomplete item→product mapping or malformed saved identities require reconciliation instead of an arbitrary choice.
- Positive finite saved Design serials retain their numeric identities, including valid imported non-contiguous values. The source selection never renumbers an order parent or its children.
- Saved source images require transferred image bytes. Desktop-only filesystem images and shared paths are not silently treated as successful web image migration.
- No Design components, gross/pieces, stock/tag transitions, Tour-specific Design help, complete tax/MRP/repricing chain, or full module parity are claimed by this slice.
- The shared desktop `MS_HELP.cs:2148–2280` additionally uses Up/Down row navigation, Left/Right search-column selection with search reset, Enter on the current grid row, Backspace search editing and F1 create/sub-create flags. This picker provides keyboard-accessible Tab/Enter actions, Escape and explicit multi-field search, but does not claim those remaining shared-help commands or exact column-specific search behavior. Their context flags and create destinations need a separate source-backed implementation card.
- Preservation differences and unsupported precision branches need explicit desktop/business acceptance; no acceptance is inferred from passing web tests.
