## Repeat values and identities

`packages/core/src/designCalc.ts` supplies the shared `designRepeatValues` resolver and repeat events. It resolves each known original header to its configured replacement, then selects repeat configuration using that replacement label. Visibility does not disable repeat: a hidden configured TagCost, for example, still copies without arithmetic. Explicit zero, empty values and extra stored precision retain their meaning at copy time. No repeat event recalculates parent totals, child amounts, conversion or labour.

Parent text metadata (page/design/style/group/size/die/karigar) copies in the draft creation operation; numeric/calculation fields also receive a repeat snapshot event. The server accepts only fields allowed by its current company configuration and only on a new parent. Metadata is kept out of the calculation event so a later metadata edit cannot be overwritten by replay. A snapshot is necessary: subsequently editing the preceding parent must not retroactively alter the already-created row.

Child repeat is derived on the server from the preceding child's replay state. It requires a new target and a same-parent, immediately preceding source. It includes supported transient old-weight trackers when configured. It cannot be reapplied to an existing/hydrated child. Parent/child serials, old-parent identity, saved-image identity and unrelated children are never copied. Serial allocation is monotonic within the editing session, including after deleting a newly added row.

Conflicting repeat flags for the same renamed label, and an enabled repeat with a blank replacement label, fail with a reconciliation message. The desktop selects its first matching metadata row; the web does not silently select between contradictory configurations. Runtime culture/case matching of `DataView.RowFilter` is not observed here.

## Ordered Enter behavior

1. Parent Gross Enter validates the draft first. It explicitly commits the source calculation even if the entered number is unchanged, ensures the selected parent's child editor has an entry row and focuses that parent's last child Item. An invalid number retains the draft, focus and existing identities. No child is allocated after failed validation.
2. Child Item Enter resolves the current company's item defaults, even when the entered code equals the current code. The field advances only after that operation succeeds. Browser lookup selection uses `LookupPicker advanceOnPick={false}` and the Design page's own scoped focus request.
3. Child PcsWt Enter applies the source's nonzero-pieces/nonzero-piece-weight karigar-weight assignment before normal leave-cell calculations.
4. Child Weight Enter tests the **previously committed** pieces and gross weight. When both are zero, zero current NetAmt receives the item default rate, then Rate clears, before the newly typed weight is committed and normal component calculation runs. This is not restricted to new books or fixed-rate items in the desktop branch.
5. NetAmt Enter commits the value and calculation, then advances to the next child's Item or appends/repeats a fresh child at the end.
6. Blank child Item Enter exits to the next source parent column relative to the parent origin. A temporary, untouched and completely blank new child can be discarded without calculation; an existing or populated row is preserved. Gross-origin entry therefore returns to OtherWt unless that column is configured hidden.
7. The terminal supported parent field advances to the next parent's PageNo or appends/repeats a new parent. Ctrl+D (and Cmd+D on the web) opens a scoped confirmation; cancellation changes no row, and confirmation removes only the selected parent/child context.

Arrow movement follows supported source field order and active parent selection. Left/right movement retains native browser caret editing until the input boundary. Up/down switches the appropriate grid row. Selection and unchanged blur keep round 2's nonmutating preservation behavior.

`apps/web/lib/designBookKeyboard.ts` is a pure navigation decision helper. `apps/web/lib/designBookDraft.ts` owns draft/event ordering, repeat snapshots and invalid-input atomicity. The page uses synchronous editor state references for event ordering, then requests focus after React commits. Focus requests carry the origin and loaded-document context; intentionally selecting another control or changing scope cancels stale focus. Pending item/default requests cannot cause a second Enter or a stale result to mutate another row.

## API replay and storage

`apps/api/src/modules/masters/designBook.ts` replays events in order against the saved parent/child snapshot using the server's versioned policy. Item defaults sent by clients are ignored. The Weight Enter default is resolved from the current replay child's scoped item only if the prior-state zero condition applies. Save verifies the journal's component set against the submitted stable identities.

The desktop keyboard branch can explicitly clear a numeric Rate cell. Its database save uses numeric conversion; the web converts only explicit empty numeric strings produced by calculation replay to zero. Loaded database NULLs remain NULL. Ordinary imported/manual API numeric validation is unchanged. A real database test found and verified this distinction; it was not only a frontend test expectation.

Existing optimistic locking, create/update authority, company/product/book validation, scoped Design images, ordered parent/child identity preservation and lossless unchanged saves remain in force. No new route or schema was needed for repeat/keyboard semantics. The shared core export and LookupPicker option were integrated by the root agent.

## Explicit differences and remaining work

These are deliberate preservation differences **pending desktop/business acceptance**, not accepted deviations:

- Hidden source EnterCell clearing is not copied: hidden imported data remains intact until an explicit edit/calculation requires change.
- The Weight Enter source reads mutable global `DC_Main.Tbl.Rows[0].OTH_RATE`. After loading or unrelated lookups that table may have stale/absent context. The web resolves the current child's scoped Item master. Paired desktop replay is still required for the stale/global context branch.
- Identity/image/internal-row columns cannot be overwritten by repeat metadata. Child deletion uses stable identity removal, not a cleared positional row that could lose ownership or collide with later rows.
- Browser left/right arrows preserve caret editing until the boundary; navigation/unchanged blur does not reproduce incidental source recalculation or clearing.
- An untouched temporary child created for component entry can be discarded on blank Item exit without committing an empty persistent row.

Open X11 work still includes diamond and descriptive child master selectors, Design-specific style/group/Karigar lookup variants and source registration conditions, Book F1/global Escape equivalents, downstream Design-to-Order design/component/image transfer, broader registration/customer/configuration matrices, exact desktop-observed replay and business signoff. The rich lifecycle, calculation and repeat slices do not establish complete X11 parity or a production conversion percentage.

For a subsequent bounded Design-to-Order task, first trace the actual desktop selection handler and parent/component identity projection, then pair it with the existing order API and image-source ownership contract. Do not copy image IDs or child rows between entities based only on matching design text. Keep that task separate from concurrent Tour Order UI work.
