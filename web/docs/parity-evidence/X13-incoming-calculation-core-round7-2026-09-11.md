## Public contract

`createSaleReturnIncomingState({rowIdentity,raw,cells,cacheMode})` clones and freezes a complete raw string/null snapshot, visible source-indexed string cells and a separate cache map. Row identity is an opaque complete persisted/source identity, not visual row0 or array position. Unknown hidden cells and original reference fields remain untouched. The caller owns the raw-to-visible projection; this constructor does not format, parse or recalculate imported values.

`cacheMode:'saved'` copies visible10/12/16/17/19/23/21/37 into caches45/46/47/48/49/58/66/67 respectively, without a row calculation or journal entry. This models saved cache seeding on already-projected visible strings, while preserving exact raw decimals, SQL NULL, empty string and microsecond clocks separately. `cacheMode:'provided'` retains the explicitly supplied caches for an existing live/new/post-copy grid snapshot. It does not invent new-row defaults or admit a tag.

`reduceSaleReturnIncoming(state,event,policy)` accepts either a `leaveCell` with the original editor text, active source column, row identity and explicit source guard context, or a `calculateAfterCopy` with a declared resolved-action cause. A `leaveCell` guard skips the event when clearing, row0, editor hidden or committed width0. Text-only source columns commit text without calculation. Numeric source columns format according to their source0/2/3-decimal case and run the ordered calculator even if the number was unchanged. Item column1 is explicitly unsupported because its tag-admission branch is outside this module. Unknown hidden columns with no source switch case skip without inventing a write. The separate gross Enter action at4383–4397 (zero-gross validation, editor hide and child-grid focus) is not exposed as a kernel event yet; an integration must model that action explicitly and must not synthesize a second blur calculation after the editor becomes hidden.

Results are `applied`, `skipped` or `rejected`. Applied state has frozen visible/caches plus an appended frozen event/settings journal entry. `aggregateRequired:true` reports that the source would next invoke aggregate callbacks; the reducer does not execute them. Text events set it false. Every skipped/rejected event returns the **same prior state object**, preserving all visible cells, caches, raw data, row identity and journal. Rejection supplies the original attempted event and a recoverable stage-specific diagnostic. There is no partial state mutation, automatic replay, retry, source selection or persistence.

Policy fields are `saleAmountType`, `labourRoundingDecimals`0–3, `labourIncludesGhat`, `generateLabourRate` and `fineColumnWidth:number|null`. They represent resolved effective desktop settings. This pure function does not query CO_SET/CO_SET_NEW/COL_DETL, choose the active book, normalize source setting overrides or establish their version. Those remain authoritative integration prerequisites.

## Calculation ownership and exact decimal policy

The Return-specific function follows all eleven ordered source stages: ghat before net, independent fine cache blocks, configured metal basis, item-rate cache invalidation, metal amount, percentage rates, labour-rate versus manual-amount generation, discount/tag labour, MRP, non-MRP/manual total and final tax cache. It intentionally does not call the Order or Design state machines.

Literal source behavior is retained: zero item rate can retain old metal; changed zero labour rate clears labour amount; ghat can use old net; zero discount percentage can retain the discount amount; basis+pieces cancellation skips metal; incoming labour rounds to whole rupees while tag labour uses configured precision; K generation/manual-total/tax inverse formulas differ; unchanged nonzero tax can copy total into net on a later event; MRP tax intermediates can be overwritten; manual negative residual labour becomes empty text while tax residual labour may remain negative. These are source-literal observations that still need executable desktop/business acceptance before production numeric saving.

Original manual-total editor text is retained separately from its rounded cell. The source compares that original value and updates the visible labour percentage whenever the active column is36, even when the editor equals computed total. Cache66 is not fabricated from the new visible percentage. Cache58 retains the source's different plain-number textual representation after manual inversion.

All numeric cell operations use a **local** Decimal clone with100 significant digits; there is no global Decimal configuration change or Number conversion of business values. New money primitives `decimalCellText` and `roundHalfEvenDecimal` preserve existing number-returning exports. Explicit source Math.Round sites use midpoint-to-even; cell formatting uses the selected mathematical half-up interpretation. Exact decimal literal arithmetic does **not** prove legacy Double/Val/Strings.Format binary, framework or culture behavior. Known uncertain midpoint and division probes remain open, including1500×(1001/1000),1.005,2.675 and0.0005 under the real desktop runtime.

Plain decimal text or blank is accepted for numerical evaluation; blank evaluates as0 without rewriting unrelated raw NULL/blank data. Prefix Val parsing, exponent/hex text, culture/group separators, NaN and infinity are not guessed. Decimal input beyond36 significant digits,18 fractional places or magnitude1e36 is recoverably contained; intermediate/result magnitude1e60 is also contained. These explicit bounds prevent hidden arithmetic precision loss. Any unguarded source zero denominator, invalid effective setting, missing configured width or unsupported item admission returns a diagnostic and the entire prior draft. This is an intentional web containment choice, not a claim that the desktop rejects the same state.
